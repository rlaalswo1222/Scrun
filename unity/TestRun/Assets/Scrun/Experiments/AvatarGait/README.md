## 바꾼 방식 (실험 결과, 확정 아님)
1. **걷기와 달리기를 섞지 않는다**: 상태 두 개(Walk, Run)로 나누고 바뀌는 순간만 0.25초 교차. 7.5 km/h 이상이면 달리기, 6.5 km/h 이하면 걷기(사이는 지금 상태 유지). 근거: 사람이 스스로 걷기→달리기로 바꾸는 속도 1.89–2.16 m/s(약 6.8–7.8 km/h, Hreljac 외 2005 JSSM에 정리된 선행 연구 범위)
2. **새 아바타의 달리기는 Standard Run부터**: Jogging·Slow Run을 짧은 다리에 입히면 8 km/h에서도 빠른 걷기처럼 보였다(cyc_tr_sheet). Standard Run을 0.77배로 틀자 한 걸음 만에 확실한 달리기 자세(cyc_tr2_sheet)
3. **체형 보정(달리기 때만)**: 몸통 12° 뒤로, 고개 14° 위로, 위팔 14° 바깥으로. 보정 전에는 큰 머리 때문에 몸이 앞으로 쏟아지고 얼굴이 바닥을 보며 손이 가슴 앞에서 교차했다(cyc_r10_sheet → cyc_r10b_sheet)
4. 걷기는 보정 없이도 자연스러움(cyc_w5_sheet)

## 빠른 걷기가 어색한 원인 검토 (11/17 2차, 상준 지적: 무릎·발 움직임)
**결론: 메시를 다시 뽑을 필요는 없다.** 원인은 두 가지.
1. **리깅 가중치(고침, v4)**: v3 FBX에서 신발 98점 중 66점·밑창 34점 중 18점이 정강이 뼈에도 붙어 있어 발목을 굽히면 신발이 휨. 무릎은 허벅지·정강이 섞임 구간이 높이 29–45cm(16cm, 다리의 30%)라 경첩이 아니라 고무관처럼 휨. 발끝 뼈는 옆으로 누워 있었음. → `art/avatar/scripts/fix_leg_weights_v4.py`로 신발·밑창 = 발 100%, 다리 관은 무릎 ±3.5cm·발목 ±2.5cm에서만 섞음, 발끝 뼈 앞으로. 결과 `avatar_lowpoly_rigged_v4.fbx`·`avatar_work_v4.blend`(v3는 그대로), 전후 `art/avatar/legfix_compare.png`. 실험 장면에 v3(가운데)·v4(오른쪽) 나란히
2. **다리 길이 대비 걸음 박자(더 큰 원인)**: 사람 보폭 그대로의 동작을 짧은 다리에 입히고 사람 속도로 움직이니 박자가 비정상
   | 속도 | 동작·재생 | 분당 걸음 수 |
   |---|---|---|
   | 걷기 5 km/h | Walking 2.08배 | 197 (Y Bot 135) |
   | 걷기 6.5 km/h | Walking 2.5배(상한) | 237, 발 8% 미끄러짐 |
   | 달리기 6.2 km/h | Standard Run 0.6배 | 93(느린 화면) |
   | 달리기 14 km/h | Fast Run 1.08배 | 228 |
   - 걷기→달리기 전환을 다리 길이에 맞춤: Froude 수 v²/(g·L) ≈ 0.5에서 두 발 동물이 달리기로 바꾼다(Alexander & Jayes 1983, Kram 외 1997). Y Bot 7.3 km/h(사람 연구값과 맞음), 새 아바타 5.9 km/h → 빌더가 다리 길이로 자동 계산(새 아바타 6.2 이상 달리기, 5.4 이하 걷기)
   - 남은 해결 후보(결정 필요): (가) Mixamo Walking의 Stride·Speed 슬라이더를 올린 "긴 보폭 걷기"를 추가로 받기(메시가 아니라 동작만) (나) 박자를 사람 범위로 묶고 약간의 미끄러짐을 허용 (다) 센서가 세는 사용자 실제 걸음 수로 재생 속도를 맞춤(아바타가 내 발과 같은 박자로 걸음, 팀 상의)

### 재생하면 이상하게 뛰던 문제 (11/20 2차, 상준 "재생 버튼 누르면 이상하게 뛴다")
켜고 끌 것을 놓친 게 아니라 세 가지 원인이었다.
