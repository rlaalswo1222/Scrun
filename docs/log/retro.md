# 세션 회고

새 회고는 위에 추가한다. 형식: 잘된 것 / 잘못된 것 / 배운 것 / 규칙으로 올릴 것.

## 2026-10-29 저녁: 중간발표 자료(전체 구성·진행·기술 문제) + 그림
- **잘된 것**: 지난 대화 기록(10/9에서 10/17)을 두 갈래로 나눠 시도를 시간순으로 복원함. 그림을 분석용 그래프가 아니라 실측 원본에서 발표용으로 다시 그림(모터 줄, 단서 3개 변화율 등)
- **잘못된 것**: "다른 날 블라인드 +5.3%"가 같은 날 13분 뒤였는데 10/12부터 문서에 계속 잘못 남아 있었음. 첫 그림에서 걸음 수를 "거의 그대로"라고 써 실제 +4%를 감출 뻔함
- **배운 것**: 보고서 수치는 문서끼리 옮기는 사이 조건(날짜·사람·같은 날 여부)이 바뀜 → 원본 meta의 시각으로 확인해야 함
- **규칙으로 올릴 것**: 보고서에 쓰는 수치는 `data/` 원본 경로와 기록 시각을 함께 적는다(README 실측 절)

## 2026-10-29 아침: 공개 데이터·관련 연구 조사 + 에어팟 공중 시간(계획 0011, 0012)
- **잘된 것**: 조사를 세 갈래로 나눠 동시에 돌리고 문제별로 정리함. 방법을 결과 전에 고정했고, 실패한 그림에서 원인(발 떼기 0.2초 이름)을 찾음. 정답 있는 공개 데이터(Nijs 2021)에서 학습 7명으로 규칙을 고르고 시험 7명으로 확인해 논문 수준(11.6 ms)을 재현
- **잘못된 것**: 공중 시간을 "혼자서 속도를 맞히나"로 시험해 원래 아이디어(걸음 수가 그대로일 때 가르기)와 어긋남 → 민재가 바로잡음. `sed -i`로 CRLF 파일을 LF로 바꿔 diff가 파일 전체로 커짐(되돌림). 조사 에이전트 결과(Krumm 힘판 "미확인")를 원문과 대조해 고쳐야 했음
- **배운 것**: 에어팟은 크기 대신 수직 방향으로 봐야 공중에서 0 g 근처가 보임. 50 Hz 귀 신호로도 문턱(착지 0.2 g 위로, 발 떼기 0.3 g 아래로)이면 걸음당 약 12 ms. 공중 시간은 사람마다 치우침이 있어 보정 없이 못 쓰지만, 걸음 수에 더하면 같은 걸음 수의 속도를 가려 줌(1.20 → 0.88)
- **규칙으로 올릴 것**: 새 지표를 시험하기 전에 "이 지표가 원래 풀려던 문제"를 계획 문서 첫 줄에 적고 그 문제로 판정. CRLF 파일(`git ls-files --eol`로 확인)은 `sed -i` 대신 Edit 도구로

## 2026-10-28 저녁: 속도 오차 원인 찾기(SoundTrackDB) + GitHub + 와이어프레임
- **잘된 것**: 공개 데이터(59명, 계기판 위 폰)를 찾아 헬스장 없이 걸음 수·소리·발 닿는 시간을 하루에 판정함. 공개 전 비밀·라이선스(Mixamo, 인증서 키)를 점검하고 Poly Haven 받기를 내용까지 검증함. 커밋 규칙을 검사기로 강제
- **잘못된 것**: "올릴 때만 정확, 내릴 때 부정확"을 근거 없이 결론처럼 말함. "폰을 안 옮겼다"고 사실과 다르게 말함(앱 다시 빌드 때 옮김). `.gitignore` 줄 끝 주석으로 7GB가 스테이징될 뻔함. 시험용 51자를 45자로 잘못 셈. 기울기 계산(걸음 수)을 잡음 방향 고려 없이 해서 한 번 틀림
- **배운 것**: SoundTrackDB 조건에선 충격만으로 0.5 이내가 절반, 같은 속도 재측정 차이 0.6이 바닥. 걸음 수·소리는 충격에 더해도 거의 안 나아짐. VibRun은 프레임 옆 센서 + 압력 깔창 정답 딥러닝이라 우리 조건과 다름. 개인 메모리는 팀원 Claude에게 안 보임
- **규칙으로 올린 것**: ADR-0006(속도 추정 제약), CLAUDE.md(출시 기준·보고서 규칙·문서화 순서·이미 정한 방향·팀 git 규칙), 사람별 인수인계, `.gitignore`엔 줄 끝 주석 금지(규칙으로 올릴 것)

## 2026-10-28 새벽: 헬스장 속도 실험 + 문서 정리
- **잘된 것**: 실험 앱을 40분 안에 만들어 현장에서 바로 돌림. 원본(420Hz)을 다 남겨서, 앱이 틀렸을 때 PC 재생으로 원인을 찾고 고침(주파수 줄 중복, 합치기 규칙). 벨트만 돌 때 주파수 방식 ±0.05 km/h, 달릴 때는 충격 세기라는 새 단서를 찾음
- **잘못된 것**: 계획 없이 바로 구현함 → 합치기 규칙 실수로 화면 숫자가 튐. "양옆 발판에 서서"를 확인하지 않고 "달리는 중에도 정확"이라고 잘못 보고함. "빠른 속도 뒤 습관이 남는다"를 근거 없이 사실처럼 말함. 범위에 물결표를 써서 채팅에 취소선이 생김. 설명 없이 "큰 숫자 옆 버튼" 같은 말로 사용자를 헷갈리게 함
- **배운 것**: 이 러닝머신에선 달릴 때 발 충격이 모터 진동보다 약 1000배 큼. 걸음 수가 일정한 사람이 있음. 보정은 앱이 속도를 안내하는 게 가장 단순함(사용자 제안)
- **규칙으로 올린 것**(CLAUDE.md): 계획 → 검토 → 구현 → 리뷰 / 실험 전에 조건 확인 / 가설은 가설로 표시, 연구는 찾아서 출처 / 물결표 금지
