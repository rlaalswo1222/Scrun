# 속도 추정 아이디어 (2026-10-17, HANDOFF에서 옮김 — 전부 미검증, 보고서에 수치로 쓰지 말 것)

- **에어팟(CMHeadphoneMotionManager, 약 25Hz)**: 체공(≈0g)·접지 충격·상하 흔들림·충격 세기 → 보폭 보정 단서. 예상: 걸음 수·정지 감지는 확실, 보폭 보정은 같은 날엔 소폭 개선 가능, 다른 날 블라인드 개선은 불확실. 검증: 모델 A(걸음 수만) vs B(+에어팟 특징), 한 구간 빼고 맞히기 + 블라인드, 속도 촘촘히(8/9/9.5/10/10.5/11/12).
- **버즈 프로4**: 공식 SDK 없음, 역분석 프로토콜은 회전(쿼터니언)만 → 갤럭시는 거치대 진동 위주, 버즈는 선택 실험.
- **워치(애플/갤럭시)**: 고속 IMU·팔 흔들기·심박·자체 보폭/속도 값은 장점이나 3번째 기기 → "폰+이어폰만" 차별점·교수님 피드백 1번과 충돌, 워치 앱 별도 개발. 결론: 핵심 X, **실험 때 비교 기준**(워치 추정 vs 우리 추정 vs 실제)으로 활용 → 멘토 요청 "워치 조사"에도 대응.
- **딥러닝**: 지금 데이터(1명·5속도)로는 과적합. 공식 유지 + 보폭만 보정하는 하이브리드 추천. 순서: 기존 공식 → 선형회귀/랜덤포레스트(scikit-learn) → 작은 1D CNN, 같은 블라인드로 비교해 이길 때만 채택. 평가는 사람·날짜·러닝머신 단위로 분리. 데이터: 팀원 3명+, 2~3일, 0.5 km/h 간격, 러닝머신 2종+. 상태 구분(달림/걷기/정지/손잡이)엔 바로 쓸 만함.
- **다른 기술 후보**:
  1. **러닝머신 블루투스 FTMS**: 지원 기종이면 실제 속도 직접 수신. 앱은 "FTMS 우선, 없으면 센서 추정" 구조, 학습 데이터 자동 라벨링에도 활용. 할 일: nRF Connect로 헬스장 기종 지원 여부 확인.
  2. **모터·롤러 진동 주파수**: 롤러 회전 주파수 ∝ 벨트 속도(대략 8~20Hz 범위로 추정) → 사람과 무관하게 속도 측정, 기종별 1회 보정. 위험: 상업용 기기 방진, 착지 충격에 묻힘, 거치대 흡수. 가능성 반반 이하지만 확인 비용 낮음. 테스트: 사람 없이 벨트만 6/8/10/12 km/h 각 30초, S22 최대 샘플링으로 거치대 기록 → 스펙트로그램에서 속도 따라 움직이는 봉우리 확인(없으면 포기) → 달리면서 재확인 → 기종 2개.
  3. 보조: 속도 변화점 검출 + 평활(칼만), 시작 속도 입력 후 변화만 추적.
- 10/12 실측 원본 파일 위치 미확인(프로젝트엔 `data/synthetic/`만 있음) → 찾으면 주파수 분석 가능.
