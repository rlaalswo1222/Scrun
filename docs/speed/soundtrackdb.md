# 공개 데이터 SoundTrackDB로 충격 + 걸음 수 공식 확인 (계획 0006, 2026-10-28)

- 데이터: [SoundTrackDB](https://github.com/Columbia-ICSL/SoundTrackDB), J. Nie 외, "SoundTrack: A Contactless Mobile Solution for Real-time Running Metric Estimation for Treadmill Running in the Wild", IMWUT 9(2) 42, 2025, DOI 10.1145/3729486, MIT 라이선스
- 조건: 러닝머신 계기판 위 폰 가속도 100Hz, 공공 헬스장 13곳, 정답 = 설정 속도(5에서 10 mph = 8.0에서 16.1 km/h, 정수 mph라 속도 간격 1.6 km/h)
- 원본 `data/external/soundtrackdb/` (가속도 362개 사용, 시간 열이 깨진 d77_P26_8_0 제외), 스크립트 `speedlab/exp/soundtrackdb.py`
- 방법: SpeedLab(StepSpeed.cs)과 같은 충격 세기·걸음 수 계산. 파일 앞뒤 30초 버리고 20초 창, 창 중앙값을 세션 한 점으로. 같은 사람·같은 날 = 한 묶음
- 규모: 세션 344개, 묶음 131개, 59명. 속도 2가지 이상 묶음 89개, 3가지 이상 41개, 보정 3개 + 시험할 속도가 남는 묶음 18개

## 결과
1. **방향은 사람·헬스장이 달라도 같음:** 89개 묶음 중 97%에서 빠를수록 충격이 셈. 걸음 수는 84%에서 늘어남(중앙값 1 km/h당 2.1 spm)
2. **정확도는 우리 1명 기록보다 훨씬 나쁨** (남은 속도 맞히기, 오차 크기)

| 보정 | 오차 중앙값 | 90% | 0.5 이내 | 0.3 이내 |
|---|---|---|---|---|
| 보정 없음(다른 사람들 공식) | 1.64 | 3.72 | 15% | 9% |
| 1개 속도(기울기는 다른 사람들 값) | 0.84 | 2.57 | 30% | 16% |
| 2개 속도, 충격만 · 보정 범위 안 | 0.53 | 2.36 | 48% | 37% |
| 2개 속도, 충격만 · 범위 밖 | 1.05 | 5.72 | 29% | 18% |
| 3개 속도, 충격만 · 범위 안 | 0.44 | 1.94 | 52% | 41% |
| 3개 속도, 충격만 · 범위 밖 | 0.90 | 2.99 | 34% | 21% |
| 3개 속도, 충격(이 사람) + 걸음 수(기울기는 다른 사람들) · 범위 안 | 0.45 | 1.91 | 53% | 39% |
| 3개 속도, 충격(이 사람) + 걸음 수(기울기는 다른 사람들) · 범위 밖 | 0.79 | 2.75 | 37% | 22% |
| 3개 속도, 충격 + 걸음 수 (맞출 값 3개) | 0.96 | 5.18 | 30% | 16% |

   - 3개 보정·범위 안을 사람별로 보면 오차 중앙값 0.24(하위 25%)에서 0.90(상위 25%), 최대 1.94 → 사람마다 차이가 큼
   - 걸음 수를 더해도 범위 안은 그대로(0.44 → 0.45), 범위 밖만 조금 나아짐(0.90 → 0.79). 걸음 수 기울기까지 이 사람 점으로 맞추면(3점에 3개 값) 남는 점이 없어 오히려 튐
3. **잡음 바닥이 높음:** 같은 사람·같은 날·같은 속도로 두 번 뛴 43쌍에서 충격 차이를 속도로 바꾸면 중앙값 0.59, 90% 2.12 km/h. 한 세션 안 20초 창끼리도 표준편차 0.35 km/h. 이 조건에선 충격만으로 0.5 이내를 꾸준히 내기 어려움
4. **기울기가 우리와 다름:** 이 데이터는 1 ln(충격)당 6.2 km/h(묶음별 중앙값 7.7), 우리 10/28은 3.3 → 여기선 속도가 올라도 충격이 덜 커짐(그만큼 잡음에 약함). 우리 기록을 100Hz로 낮춰도 3.3 그대로라 샘플링 차이는 아님. 원인(러닝머신·거치·폰·속도 범위)은 미확인

5. **걸음 수만으로는 더 나쁨** (`speedlab/exp/soundtrackdb_cad.py`): 3개 속도 보정·범위 안 오차 중앙값 0.90(0.5 이내 32%), 1개 보정 1.23, 보정 없음 1.65(키를 넣어도 1.82). 걸음 수는 1 km/h당 2에서 4 spm만 변하는데, 같은 속도로 두 번 뛰면 걸음 수가 중앙값 3.1 spm 달라짐(속도로 약 0.8 km/h)

6. **발 닿는 시간(GCT)을 더하면 나아짐 — 단, 정답 GCT(영상 기반 YOLO 라벨)를 쓴 상한선** (`speedlab/exp/soundtrackdb_gct.py`)
   - 1 km/h 빨라질 때 발 닿는 시간 중앙값 15 ms 줄어듦(96% 묶음), 공중 시간 12 ms 늘어남(87%)
   - 충격 + 발 닿는 시간(발 닿는 시간 기울기는 다른 사람들 값): 3개 보정 범위 안 0.44 → **0.36**(0.5 이내 52% → 57%, 90% 1.94 → 1.48), 범위 밖 0.90 → **0.53**. 2개 보정 범위 안 0.53 → 0.40. 1개 보정 0.84 → 0.67. 보정 없음 1.64 → 1.04(충격 + 발 닿는·공중 시간 + 걸음 수)
   - 발 닿는 시간 기울기까지 이 사람 점으로 맞추면 다시 나빠짐(0.63) → 기울기는 다른 사람들 값을 빌리는 게 맞음
   - 같은 속도로 두 번 뛰면 발 닿는 시간 차이 중앙값 8.2 ms(속도로 0.41 km/h)
   - 남은 문제: 폰 가속도(계기판 위)로 발 닿는 시간을 잴 수 있는지. 논문은 소리로 잼, "가속도는 소리보다 나은 게 없었다"
7. **폰 가속도(100Hz)로 잰 충격 모양은 안 통함** (`speedlab/exp/soundtrackdb_shape.py`)
   - 영상 착지 시각에 맞춰 평균 내도 폰 신호의 걸음 모양이 흐림(봉우리가 착지 뒤 90에서 440 ms로 들쭉날쭉) → 이 데이터에선 정렬 또는 충격 전달이 약함
   - 폰 신호에서 찾은 봉우리 기준 평균 펄스의 반높이 폭·앞뒤 꼬리: 속도를 뺀 나머지끼리 정답 GCT와 상관 +0.15 이하
   - 충격에 더해도 3개 보정 범위 안 0.44 → 0.48에서 0.54(나아지지 않음)
   - 한계: 100Hz(한 칸 10 ms, 1 km/h당 GCT 변화 15 ms). 우리 앱은 420Hz라 따로 확인 필요 → 10/28 밤 팀원 기록(보정 7 + 검증 14구간)으로 "폭을 더하면 속도 오차가 줄어드나"를 직접 봄(GCT 정답 없이도 가능)

8. **소리(폰 마이크)를 더해도 안 나아짐** (계획 0007, `speedlab/exp/soundtrackdb_audio.py`)
   - 대역(낮음 50에서 300, 중간 300에서 2000, 높음 2000에서 6000 Hz)별 발소리 크기·바탕 대비 비율, 20초 창. 소리로 걸음이 잡힌 창 74%
   - 같은 사람 안에서 속도와 상관: 충격 +0.86, 소리 +0.25에서 +0.58. 충격으로 설명 안 되는 부분과는 +0.07에서 +0.26
   - 3개 보정·범위 안: 충격만 0.44 / 충격 + 소리 0.42에서 0.48(0.5 이내 51에서 52%) / 소리만 1.15에서 1.55. 1개 보정도 0.84 → 0.80에서 0.88
   - 한계: 손으로 고른 단순한 값(대역 세기). 논문들처럼 딥러닝으로 발소리를 골라내면 다를 수 있음(미확인). 이 결과로는 마이크 제외(10/28 결정)를 바꿀 근거 없음

## 의미 (가설 포함)
- 우리 10/28 결과(평균 오차 0.28에서 0.43)는 1명·같은 날이라 낙관적일 수 있음. 오늘 밤 "다른 날" 검증과 팀원 기록이 이걸 가름
- 두 번 뛴 사이에 충격이 달라지는 원인(폰을 다시 놓음? 다른 기계? 피로?)은 이 데이터 설명에 없음 → 논문 데이터 수집 절 확인 필요
- 보정은 "평소 속도 범위를 감싸게" 해야 함(범위 밖은 오차 2배)
- 보고서에 쓸 땐 "공개 데이터(출처) 재분석"으로, 우리 앱 실측과 구분
