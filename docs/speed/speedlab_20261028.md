# 속도 실험 앱 SpeedLab 상세 (2026-10-28 새벽 헬스장, HANDOFF에서 옮김)

- Unity 별도 APK `com.scrun.speedlab` "Scrun 속도실험" (메뉴 Scrun → Build SpeedLab APK, Mono+ARMv7라 빌드 4분·32비트 경고 뜸, 본 앱 설정은 빌드 후 복원). 코드 `Assets/Scrun/SpeedLab/`(TreadmillSensor·StepSpeed·FreqSpeed·SpeedLab·SpeedLabUI), 자바 `Assets/Plugins/Android/ScrunAccel.java`(가속도 최고속, S22 = 420Hz), 권한 주입 `Editor/SpeedLabManifest.cs`. ISpeedSource 구현
- 기록: 폰 `Android/data/com.scrun.speedlab/files/SpeedLab/<시각>/`(acc.csv 원본, est.csv, events.csv) → `data/speedlab/`로 adb pull(Git Bash는 로컬 경로를 Windows 형식으로)
- **결과 1 (벨트만, 사람은 옆 발판)**: 모터 진동 줄 k ≈ 2.82 Hz per km/h + 배음. 고친 추정(줄 중복 제거 8%, 3 km/h 미만 제외, 보정 범위 ±4, 주변 고정 진동 칸 무시, 연속성 추적) → 6/7/8/9/10/12 km/h 모두 ±0.05 km/h, 바뀐 뒤 약 1.5초. 옆 러닝머신 진동은 신뢰도 0.4 수준(우리 것 0.75 이상)이라 기준 0.55로 거름
- **결과 2 (직접 달림)**: 발 충격이 모터 진동보다 약 1000배 세고, 걸음 박자 배음(2.93Hz 간격)이 가짜 줄을 만들어 **달리는 중 주파수 방식 실패**(8·10 모두 5로 추정). 걸음 수는 잘 잡히나(신뢰 0.9) 이 사용자는 8 km/h 176, 10 km/h 177 spm으로 거의 일정 → **걸음 수만으로 속도 구분 불가**
- **결과 3 (7/8/9/10 각 20초 + 다른 기록 8/10 블라인드)**: 발 충격 세기(8Hz 이상 포락선 봉우리 중앙값)가 속도에 따라 2.5/3.3/3.9/5.9로 증가. 속도 = a + b·log(충격 세기), 4초 창: 한 속도 빼고 맞히기 7→7.46, 8→8.14, 9→8.51, 10→10.59 / 블라인드 8→8.36, 10→10.24 (약 5%). 걸음 수 단독은 전부 8.5 근처로 쓸모없음. 신발·거치 위치·피로 영향 미검증
- **결과 4 (실시간, 앱에 충격 모델 넣음, 보정은 결과 3 기록으로 계산해 폰에 push)**: 9→8.94, 7→7.77(+11%), 10→9.96, 8.5→9.36(+10%). 내려간 속도(빠른 구간 뒤)에서 과대 추정 → 피로·습관으로 충격이 남는 듯. 같은 기록에 걸음 수를 더한 모델(v = -3.73 + 2.79·ln(충격) + 0.0492·spm, 4점 보정)이면 9.00/7.41/9.77/8.99(평균 약 3.5%) — 앱엔 아직 미반영. 반응: 7→10은 2초 만에 9.4, 4초에 9.9 / 9→7은 즉시 8.5까지 내려온 뒤 8초가량 머묾. 이번 기록엔 실제 속도 버튼을 안 눌러 구간은 추정값 변화로 나눔(순서 9, 7, 10, 8.5)
- 다음: 걸음 수+충격 모델 앱 반영, 보정을 올라가는 순서·내려가는 순서 둘 다, 러닝머신 FTMS 지원 확인(nRF Connect), 에어팟 체공·머리 흔들림. 사람 없을 때(벨트만)는 주파수 방식이 매우 정확
- 앱의 걸음 추정 현재 버그: 단일 보정점이면 보폭 고정, 합침 모드는 주파수 우선(달릴 때 틀린 주파수가 신뢰도 0.55를 넘을 수 있음)
