속도 추정 작업을 시작할 때 이 파일부터 읽는다. 결정 근거는 [ADR-0004](../adr/0004-speed-estimation-running.md), [ADR-0005](../adr/0005-guided-calibration.md), [ADR-0006](../adr/0006-speed-constraints.md)(폰은 그냥 올려놓기, 입력 없음, 제외한 방법들).

- 계획 0002 상세: 발 충격은 짧은 펄스라 0에서 210Hz 전 대역을 덮음(모터와 대역이 갈리지 않음, 달림 ÷ 벨트만 파워 60배에서 10000배). 평균 발소리 빼기로 남은 세기는 원래의 35%에서 80%(rms). 예측 자리(2.80×v) 점수를 다른 자리들과 비교하면 9 km/h만 상위 0%에서 4%, 7·8·10은 상위 11%에서 100%로 우연 수준. 8 km/h는 걸음 검출이 깨끗했는데도 실패. 스크립트 `speedlab/exp/motor_tsa.py`, 그림 `img/0002_spectra_*.png`. 모터 줄 기울기는 벨트만 기록에서 2.80 Hz per km/h(8→22.38, 10→28.00)

## 실험 앱 SpeedLab
- Unity 별도 APK `com.scrun.speedlab`. 메뉴 Scrun → Build SpeedLab APK (Mono + ARMv7, 4분, 실행 때 32비트 경고 → 확인)
- 코드 `unity/TestRun/Assets/Scrun/SpeedLab/`, 고속 센서 `Assets/Plugins/Android/ScrunAccel.java`, 권한 `Editor/SpeedLabManifest.cs`. `ISpeedSource` 구현 → 본 앱 아바타에 꽂을 수 있음(아직 안 꽂음)
- 기록: 폰 `Android/data/com.scrun.speedlab/files/SpeedLab/<시각>/`(acc.csv 원본, est.csv, events.csv) → `data/speedlab/`로 adb pull. 보정 파일 `files/speedlab_calib.json`
- 현재 앱 동작: 달리는 중(걸음 신뢰 0.3 이상)이면 `속도 = a + b·ln(충격) + c·spm`(달리기 보정 4구간 이상, 계획 0005) → 모자라면 충격만 `a + b·ln(충격)`, 걸음이 안 잡히면 주파수. est.csv에 `imp_kmh`, `impcad_kmh` 둘 다 기록
- 안내 모드(계획 0003, 10/28 추가): 버튼 입력 없이 앱이 "N km/h로 맞추세요" → 맞추는 시간 → 기록 → 다음. **안내 보정**(7, 8, 9, 10, 9.5, 8.5, 7.5 각 20초, 맞추는 시간 5초, 끝나면 달리기 보정점 교체, 벨트만 점은 유지) / **안내 검증**(7, 8, 9, 10, 9, 8, 7, 10, 9, 8, 7, 8, 9, 10 각 20초: 같은 속도를 올라가며·내려가며, 맞추는 시간 10초, 보정은 안 바꿈) / **걷기 기록**(1, 2, 3, 4, 5, 6, 5, 4, 3, 2, 1 각 20초, 기록만, 계획 0004). "짧게"를 켜면 구간 5초(동작 확인용). events: `guide_mode`(1 보정, 2 검증, 3 걷기), `guide_set`, `guide_start`, `guide_end`, `guide_done`, `guide_cancel`. 에디터에서 세 모드 한 바퀴씩 확인, 폰 미확인
