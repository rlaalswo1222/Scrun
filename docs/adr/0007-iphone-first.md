# ADR-0007: 아이폰 + 에어팟을 먼저 출시 대상으로 한다

- 상태: 승인 (팀 공유 필요)
- 날짜: 2026-11-03
- 결정한 사람: 김민재

## 배경
속도 추정의 최신 결과는 계기판 위 아이폰 + 에어팟에서 나왔는데, Unity 본 앱은 안드로이드(S22)로 빌드하고 있었다. 개발자 2명이 어느 플랫폼에 코드를 쓸지 정해야 끝-끝 연결(속도 → 아바타)을 시작할 수 있다. 11/22까지 3주 남음.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 아이폰 우선 | 에어팟 센서(머리 움직임)는 iOS API로만 나옴. 실시간 계산이 이미 아이폰에서 동작(Swift `SpeedEstimator`, Python 기준 구현과 차이 중앙 0.001 km/h). 한 플랫폼만 맞추면 됨 | 빌드에 맥 필요. 안드로이드 사용자 못 받음. 아이폰 고속 센서는 100 Hz(S22 420 Hz보다 낮음) |
| 안드로이드 우선 | 지금 Unity 빌드·S22 성능 확인이 있음 | 이어폰 센서 없음(갤럭시 버즈 공식 SDK 없음) → 폰만, 걷기·달리기 구분과 공중 시간 못 씀 |
| 양쪽 동시 | 사용자 범위 넓음 | 센서·속도 계산을 두 벌 유지, 3주 안에 끝-끝 하나 만들기도 빠듯 |

## 결정
아이폰 + 에어팟을 먼저 출시 대상으로 한다. Unity 본 앱을 iOS로 빌드하고, 센서 읽기와 속도 계산은 이미 있는 Swift 코드를 Unity iOS 네이티브 플러그인으로 붙여 Unity에는 속도만 넘긴다(`ISpeedSource`). 안드로이드(S22 SpeedLab)는 실험 도구로 유지한다.

## 이유
- 아이폰 안 실시간: 같은 날 보정 직후 달리기 0.16 km/h, 폰만 0.12(1명·1회, [live_iphone.md](../speed/live_iphone.md))
- 에어팟으로만 되는 것: 걷기·달리기 구분(공중 시간 0), 걸음 수가 같을 때 속도 가르기([airpods_flight.md](../speed/airpods_flight.md))
- 아이폰 100 Hz로도 충격 방식이 속도를 따라감(10/29, [README](../speed/README.md))
- 에어팟이 끊기면 폰만으로 계산하는 경로가 이미 있음

## 결과와 위험
- 맥에서 Xcode로 빌드·설치해야 함. 팀 맥북 1대 → 빌드 담당·순서 정하기
- 출시·팀 밖 테스트(TestFlight)에는 Apple Developer Program 가입(연 회비)이 필요. 무료 계정 설치는 기간 제한이 있음 → 재료비 항목 확인
- 에어팟 머리 움직임을 주는 기종이 정해져 있음(에어팟 프로·맥스 등) → 지원 기종 목록을 확인해 앱 안내에 넣기. 지원 안 되는 이어폰이면 폰만으로
- Unity 섬 월드 성능은 S22에서만 잼(30 fps) → 아이폰에서 프레임·발열 다시 재기
- 안드로이드 사용자는 당분간 못 받음. 다시 검토할 조건: 아이폰 출시 뒤, 또는 폰만 방식이 다른 날·다른 사람에서 에어팟 포함과 비슷한 오차를 낼 때
