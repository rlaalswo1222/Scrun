# ADR-0005: 보정은 앱이 속도를 안내하고, 사용자는 버튼을 누르지 않는다

- 상태: 승인 (SpeedLab에 구현, 본 앱은 구현 전)
- 날짜: 2026-10-28
- 결정한 사람: 사용자

## 배경
보정은 "실제 속도 X일 때 걸음 수·충격 세기가 Y"라는 짝을 모으는 일이다. 앱은 실제 속도를 모르므로 누군가 알려줘야 한다. 10/28 실험에선 사용자가 달리면서 실제 속도 버튼을 눌렀고, 마지막 기록에선 한 번도 못 눌러 구간을 추정으로 나눠야 했다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| 사용자가 달리면서 실제 속도 버튼 입력 | 구현 단순 | 빠뜨리거나 잘못 누름(10/28 실제 발생) |
| 벨트만 돌 때 모터 주파수로 앱이 속도를 직접 측정 | 입력 실수 없음 | 러닝머신마다 주파수 비율을 먼저 알아야 함, 복잡 |
| 앱이 "8로 맞추고 달리세요"라고 안내 | 단순, 입력 없음, 순서(오름·내림)를 앱이 통제 | 사용자가 속도를 잘못 맞추면 틀린 보정 |

## 결정
앱이 속도를 하나씩 안내한다: 화면·소리로 "N km/h로 맞추고 달리세요" → 5초 대기(벨트 가속) → 20초 기록 → 다음 속도. 순서는 오름과 내림을 둘 다 포함한다(예: 7, 8, 9, 10, 9.5, 8.5, 7.5).

## 이유
- 사용자 제안. 가장 단순하고, 달리는 중 버튼 입력이 사라짐
- 내림 순서를 넣으면 10/28에 본 "내린 속도 과대 추정"도 보정에 반영됨

## 결과와 위험
- 사용자가 속도를 잘못 맞추는 경우 → 나중에 필요하면 모터 주파수로 확인하는 기능 추가 (선택)
- 보정 시간: 7단계면 약 3분 달리기

## 추가 결정: 언제 보정하나 (2026-10-28, 사용자)
보통 같은 헬스장·같은 러닝머신에서 뛰므로 매번 보정하지 않는다. 보정값은 사람 × 헬스장마다 저장(서버).
1. 처음 사용: 첫 달리기 앞 3분(워밍업 형태), 속도는 사용자가 평소 뛰는 속도 주변
2. 다른 헬스장: 위치로 인식. 위치 권한이 없으면 헬스장 선택으로 대신. 예전 헬스장으로 돌아가면 저장된 값 사용
3. 폰 변경: 다른 기종일 때만(같은 기종은 이전 값 사용, 가설)
4. 인증 사진의 거리와 추정 거리가 최근 계속 안 맞을 때: 기준(최근 몇 회, 몇 %)은 다른 날 검증 실험 뒤 정함. 계기판 숫자 읽기(OCR)가 있어야 동작
- 평소엔 인증 사진으로 보정값을 조용히 조금씩 고침. 신발·거치 각도·같은 헬스장 안 다른 기종은 4번으로 잡힘
- SpeedLab 구현: 계획 0003 (안내 보정·안내 검증 모드)
