# ADR-0006: 속도 추정은 폰을 계기판에 그냥 올려놓은 상태에서, 사용자 입력 없이 한다

- 상태: 승인
- 날짜: 2026-10-28
- 결정한 사람: 사용자

## 배경
속도 오차를 0.5 km/h 아래로 줄이려고 여러 단서를 검토하면서(계획 0002, 0006, 0007, [soundtrackdb.md](../speed/soundtrackdb.md)), 어떤 방법을 써도 되고 어떤 방법은 앱의 정체성과 맞지 않는지 선을 그어야 했다. 이 앱의 차별점은 **외부 장비·입력 없이 폰 하나로 러닝머신 속도를 작은 오차로 추정**하는 것이다.

## 선택지 (검토 후 제외한 것)
| 방법 | 제외 이유 |
|---|---|
| 러닝머신 블루투스(FTMS)로 속도 받기 | 외부 연결에 기대면 차별점이 사라짐. 지원 안 하는 기계도 많음 |
| 반자동 입력(사용자가 속도를 입력·버튼으로 알림) | 달리는 중 입력 부담, 차별점과 충돌 |
| 마이크(소리) | 헬스장 소음. SoundTrackDB 재분석에서도 충격에 더해 나아지지 않음(계획 0007) |
| 러닝머신 버튼 누름 감지 | 3, 6, 9 같은 바로가기 버튼이 있으면 누른 횟수로 속도를 알 수 없음 |
| 거치대에 고정한다고 가정 | 사용자는 계기판에 그냥 올려놓음. 거치대가 없는 기계도 있음 |
| 매 달리기마다 안내형 시작(아는 속도로 1분 등) | 매번 보정은 귀찮음 → **최후의 수단** |

## 결정
- 폰은 **계기판 위에 그냥 올려놓은 상태**를 전제로 한다(위치·각도는 매번 조금씩 다를 수 있음)
- 사용자에게 속도를 입력받지 않는다. 쓸 수 있는 신호: 폰 가속도(충격·걸음·모터 진동), 자이로, 이어폰 센서, 계기판 인증 사진(달린 뒤)
- 보정은 사람 × 헬스장마다 처음 한 번(ADR-0005의 계기). 매번 다시 보정하게 하는 설계는 다른 방법이 모두 안 될 때만

## 이유
- 사용자 판단(2026-10-28). 차별점 = 외부 장비·입력 없이 추정
- 검토 근거: [docs/speed/README.md](../speed/README.md), [soundtrackdb.md](../speed/soundtrackdb.md)

## 결과와 위험
- SoundTrackDB(계기판 위 폰, 59명)가 우리 조건과 가까움. 거기서 충격만으로 3개 속도 보정·범위 안 오차 중앙값 0.44 km/h, 0.5 이내 52% → 이 제약 안에서 0.5 미만을 누구에게나 내는 방법은 아직 없음
- 남은 후보(입력 없이): 걸을 때 모터 진동으로 그날 기준점 잡기, 폰 기울기로 보정, 인증 사진으로 계속 학습. 다 안 되면 어떤 제약을 풀지 이 ADR을 다시 검토
