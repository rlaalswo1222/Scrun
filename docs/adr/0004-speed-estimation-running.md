# ADR-0004: 달릴 때 속도는 "걸음 수 × 보폭(발 충격 세기로 추정)", 모터 주파수는 벨트만 돌 때 쓴다

- 상태: **잠정** (피험자 1명, 하루치 데이터. 블라인드 검증 후 승인)
- 날짜: 2026-10-28
- 결정한 사람: 사용자와 Claude (헬스장 실측 후)

## 배경
폰(러닝머신 거치대)만으로 달리는 속도를 실시간으로 알아야 아바타가 그 속도로 달린다. 10/12에는 "걸음 수 × 보폭(걸음 수로 보정)"으로 평균 3.5%를 얻었지만, 10/28 실측에서 이 사용자는 속도를 올려도 걸음 수가 거의 같았다.

## 선택지 (10/28 실측 결과 포함)
| 선택지 | 결과 | 비고 |
|---|---|---|
| 걸음 수 × 고정 보폭 | 7에서 10 km/h를 전부 8.5 근처로 추정 | 걸음 수가 일정한 사람에겐 무용 |
| 모터·롤러 진동 주파수 | 벨트만: ±0.05 km/h / 달림: 실패 | 발 충격이 약 1000배 커서 묻힘 |
| 발 충격 세기만 | 0, +11, 0, +10% | 빠른 구간 뒤 내린 속도에서 과대 |
| 걸음 수 × 보폭(충격 세기) | 0, +6, −3, +5% (PC 재계산) | 계수 2개, 물리 공식 유지 |
| 러닝머신 블루투스 FTMS | 미확인 | 지원 기종이면 가장 정확 |
| 에어팟 체공·머리 흔들림 | 미확인 | 이어폰 필요 |

## 결정
- 달리는 중: `속도 = 걸음 수 × 보폭`, `보폭 = a + b·ln(충격 세기)`. a, b는 사용자별 보정(최소제곱)
- 사람이 없을 때(벨트만): 모터 진동 주파수 — 보정 확인용
- FTMS를 지원하는 러닝머신이면 FTMS 우선 (확인 후 별도 ADR)

## 이유
- 실측에서 가장 오차가 작았고, 계수가 적어 과적합 위험이 낮음
- 걸음 수 × 보폭이라는 물리 구조를 유지하므로, 걸음 수가 변하는 사람(10/12 데이터)에도 자연스럽게 맞음

## 결과와 위험
- 충격 세기는 신발, 거치 위치, 러닝머신 기종, 피로에 따라 달라질 수 있음 → 다른 날·신발 블라인드 검증 필요
- 내린 속도에서 과대 추정 원인 미확인 (가설: 피로, 순서, 오름차순 보정)
- 반응: 올릴 때 2에서 4초, 내릴 때 더 느림(8초 정체 사례)
- 다시 검토할 조건: 블라인드 오차가 8%를 넘거나, 다른 러닝머신에서 충격 세기가 속도를 따라가지 않을 때
