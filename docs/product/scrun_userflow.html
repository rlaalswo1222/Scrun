스크런 유저플로우

사용자가 목표를 이룰 때까지 거치는 화면, 결정, 앱이 알아서 하는 일, 실패했을 때의 길을 한 장에 그린 예시입니다. 화면 목록만 늘어놓은 것과 무엇이 다른지 보이도록 스크런의 두 가지 핵심 흐름으로 만들었습니다.

좋은 유저플로우의 조건

시작과 끝이 분명함어디서 들어와서 무엇을 이루면 끝나는지 한 줄로 말할 수 있다.
종류를 구분함화면, 사용자의 결정, 앱이 알아서 하는 처리를 다른 모양으로 그린다.
실패 경로가 있음권한 거부, 연결 끊김, 건너뛰기처럼 계획대로 안 될 때 어디로 가는지 그린다.
사용 상황을 반영함러닝머신 위에서는 손을 거의 못 쓴다. 달리는 중 조작은 최소로.
화면 수가 최소목표에 필요 없는 화면은 뺀다. 남은 화면 노드가 그대로 와이어프레임 목록이 된다.

나쁜 예와 좋은 예

나쁜 예
로그인 → 홈 → 달리기 → 결과

화면 이름만 나열했다. 권한을 거부하면? 이어폰이 없으면? 언제 달리기가 시작되는지, 앱이 뒤에서 무엇을 하는지 알 수 없어 와이어프레임이나 구현으로 넘어갈 수 없다.

좋은 예
홈 → 코스 선택 → 준비 → [걸음 감지 → 자동 시작] → 달리기 ⟲ 자동 일시정지 → 결과 → [보정 갱신·저장]
