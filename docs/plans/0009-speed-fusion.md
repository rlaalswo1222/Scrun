# 계획 0009: 걷기·달리기를 가르고, 공통 기울기 + 사람별 한 값으로 속도 추정 (PC에서 먼저)

- 상태: **완료 — 대부분 효과 없음** (2026-10-29 승인·구현·평가). 걷기·달리기 가르기는 됨, 공통 기울기·인증 사진 보정·계단식 묶음은 오차를 못 줄임, 에어팟만 줄임(1명·1회). 결과 [fusion.md](../speed/fusion.md)
- 걷기 걸음 수가 두 사람 같았던 건 다리 길이가 비슷해서일 수 있음(10/29 민재) → 공통 공식으로 확정하지 않음
- 작성: 2026-10-29
- 왜: 10/29 헬스장 기록에서 (1) 걷기를 달리기 공식에 넣으면 크게 틀림(B의 7 km/h), (2) 다른 날 오차가 대부분 일정한 치우침(민재 +0.5, 가설 → 평가에서 철회), (3) 보정 구간 하나가 흐트러지면 공식 전체가 흔들림(B의 9 km/h), (4) 걷기는 걸음 수가 두 사람 거의 같음(다리 길이가 비슷한 두 사람), (5) 에어팟 머리 흔들림이 폰 충격과 다른 정보(1명·1회). 공개 데이터에서도 기울기를 사람마다 맞추면 나빠졌음(SoundTrackDB 0.44 → 0.96)
- 결정(10/29 사용자): **모터 주파수는 쓰지 않음**. 기계마다 기울기를 따로 맞춰야 하고(같은 기종인데 2.80과 2.85), 옆 발판에 서는 행동에 기대며(ADR-0006), 헬스장 고정 진동(17에서 19 Hz)에 속음. 멈춤은 "걸음 없음"으로 판단

## 구조
1. 상황 판단(틱마다): 걸음 없음 / 걷기 / 달리기 (걸음 수, 충격, 에어팟 있으면 0.5 g 아래 시간)
2. 걷기: 속도 = 공통 걸음 수 공식
3. 달리기: 속도 = a(사람) + b·ln(충격) + c·걸음 수 [+ d·에어팟], b·c·d는 여러 사람 공통, a만 사람별
4. a 맞추기: 첫 보정(구간 평균 잔차) + 인증 사진(지난 기록의 평균 속도)으로 계속 고침
5. 보정 구간 품질 검사: 20초 안에서 걸음 수·충격이 흐트러지면 그 점은 버림
6. 실시간: 속도는 계단식으로 바뀐다고 보고 같은 단계 안에선 평균, 걸음 수·충격이 크게 바뀌면 새 단계
