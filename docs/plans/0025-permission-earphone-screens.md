- 상태: **승인 · 구현 중** (2026-11-10 지환 승인, 아래 "정한 것"은 지환이 고름). 브랜치 `feat/permission-screens`는 `feat/course-screens`(PR #32) 위에 쌓음
- 번호: 처음 0023으로 썼으나 민재 보정 계획(0023-calibration, ADR-0005·노션에서 이미 씀)·0024(Swift 속도 플러그인)와 겹쳐 0025로 바꿈(11/10 민재 리뷰)
- 담당: 지환(화면). 밑의 Swift(권한 4종·헤드폰 연결)는 민재(계획 0018의 5번, PR #28). 리뷰는 민재
- 기준: Figma "SCRUN" > 스크런 와이어 프레임 A-07 권한 안내(596:282), A-08 iOS 권한 팝업(596:356), A-09 이어폰 미연결(596:388), A-10 이어폰 연결됨(596:442), I-05 모션 권한 거부(611:2315). C# 모양은 `App/Native/Permissions.cs`·`Headphones.cs`, 에디터는 Fake Native 창(`docs/unity/unity_map.md` "앱 코드 묶음")

## 흐름
```text
가입 끝(ProfileScreen) ─┐
앱 시작 + 로그인됨 + 모션 권한 "아직 안 물어봄" ─┴→ A-07 권한 안내 → A-09/A-10 이어폰 → 홈
A-07 "권한 설정하기" → 시스템 팝업(A-08) 4개를 차례로(모션 → 헤드폰 모션 → 카메라 → 알림) → 다 끝나면 이어폰 화면
     모션이 거부면 → I-05(설정 열기 / 나중에)
A-07 "나중에 하기" → 이어폰 화면(모션 없이는 맵에 못 들어가므로 입장 때 다시 안내)
A-09 미연결: "연결 확인하기"(다시 읽기), "이어폰 없이 계속"·"건너뛰기" → 홈. 끼면 저절로 A-10
A-10 연결됨: 이어폰 이름, "다음" → 홈
```
- 이어폰 화면까지 끝냈는지를 이 기기에 저장한다(`PlayerPrefs`). 끝내기 전에 앱을 끄거나 설정 앱을 다녀오며 앱이 다시 켜져도 A-07부터 이어짐(이미 정한 권한은 팝업 없이 지나감). **끝낸 뒤에는 "나중에"로 권한을 미뤘어도 다시 보여 주지 않음**(빠진 모션은 맵 입장 때 막음). 다시 깔면 저장도 지워져 다시 보여 줌. 가입 끝·로그인된 채 시작·기존 회원 로그인 모두 같은 판단(`Onboarding.Begin`)
- 보정 안내(A-11)·주간 목표(A-16)·온보딩 완료(A-17)는 이 계획 밖(보정은 민재 S2, 목표는 지환 S6). 이어폰 화면 다음은 지금은 홈

## 하는 것
1. **`PermissionsScreen`(A-07)**: 네 줄(모션 및 피트니스 필수, 헤드폰 모션 선택, 카메라 필수, 알림 선택), 줄마다 지금 상태(허용됨이면 표시). "권한 설정하기", "나중에 하기"
2. **`EarphoneScreen`(A-09·A-10)**: `Native.Headphones.Status`·`Changed`로 미연결·연결됨. 모션 없는 이어폰은 "이 이어폰은 움직임 센서가 없어 폰 센서로만 속도를 추정해요", 헤드폰 모션 권한이 꺼져 있으면 "헤드폰 모션이 꺼져 있어 폰 센서로만…"(사용 가능이라고 하지 않음). 움직임 센서가 있는 이어폰이 연결됐는데 헤드폰 모션을 아직 안 물어봤으면 이 화면에서 묻는다. A-09 문구는 Figma 그대로
3. **`MotionDeniedScreen`(I-05)**: 모션이 거부·제한일 때. "설정 열기" → `OpenSettings`, 설정에서 켜고 돌아오면(`Changed`) 저절로 다음으로. 맵 입장(`MapScreen`) 전에도 모션을 보고 없으면 이 화면(코스 화면과 이음)
4. **흐름 판단을 화면 밖 순수 함수로**(`Onboarding.NeedsOnboarding`·`Next`·`BeforeMap`, 문구는 `OnboardingText`) → EditMode 테스트
5. **아이콘**: Figma 권한 아이콘 4개·이어폰 아이콘 SVG(Preserve Viewport). 이어폰 그림(A-09 "[에셋] headphone")은 에셋이 없어 뺌(빈 칸을 두지 않음)

## 정한 것 (11/10 지환)
1. **권한은 Figma대로 A-07에서 4개를 한 번에** 묻는다. Apple 지침("필요할 때 물어라")과 다를 수 있음 → 심사에서 지적되면 카메라는 S4 촬영 때로 옮긴다. 헤드폰 모션은 이어폰이 없을 때 iOS가 팝업을 띄우는지 아이폰에서 확인(가설), 안 뜨면 이어폰 화면에서 연결됐을 때 다시 묻는다
2. **A-09 문구는 Figma 그대로**("AirPods가 있으면 … 속도가 더 안정적이에요"). 지금 실측은 이 말을 받쳐 주지 않음(아이폰 실시간 1회 예비: 에어팟 포함 0.16, 폰만 0.12 km/h, 나중 분석에선 에어팟을 더하면 0.37 → 0.21–0.28, `docs/speed/README.md`) → 헬스장 실측이 쌓이면 문구를 다시 본다. 보고서·발표에는 이 문구를 성능 근거로 쓰지 않는다
3. **모션 권한 없이 맵에 들어가려 하면 입장 전에 막는다**: 상세 "맵 입장" → 모션이 아직 안 물어봄이면 팝업, 거부·제한이면 I-05

## 확인
에디터 Play + Fake Native 창: 새 사람 가입 → A-07 → 팝업 허용 → 이어폰(미연결 → Fake에서 끼면 A-10) → 홈. 모션 거부 → I-05 → Fake에서 허용으로 바꾸면 다음으로. "나중에" 뒤 맵 입장 → I-05. 앱 재시작 시 모션 안 물어봤으면 A-07부터. 아이폰(PR #28 뒤): 실제 팝업·설정 앱 왕복·에어팟 끼고 빼기

## 하지 않는 것
Swift 권한·헤드폰 구현(민재), 카메라 거부 화면 I-06(S4 계기판 촬영 때), 보정·목표·온보딩 완료 화면, 이어폰 그림 에셋(상준)
