# 계획 0040: 페이스 봇 — 서버 방에서 돌리고 모두에게 같은 자리 (BL-23, S5 민재)

- 상태: **승인(11/17 민재: 정할 것 1–5 모두 (가) 추천안) · 구현 끝, 리뷰·에디터 Play·배포 남음** (브랜치 `feat/pace-bot`)
- 담당: 민재(서버·앱 연결). 이름표 배지 모양·문구는 상준(Figma D-10 "BOT 페이스메이커" 칩)
- 기준: 공개 백로그 BL-23 ① 서버가 맵마다 봇을 배치·운영 ② 봇 수·페이스는 서버 설정값(코드에 고정 안 함, 11/06 확정) ③ 같은 맵의 모든 러너에게 같은 위치로 보임 ④ '봇' 표시 ⑤ 사람 수 + 봇 수 = 목표 인원으로 채우고 빼기(계획 0029 "미룬 것"). 11/17엔 공개 노션 API가 403이라 백로그 원문은 다시 못 읽음 → 인수인계·0029·ADR-0010에 옮겨 둔 내용 기준
- 근거: ADR-0010(실시간은 우리 FastAPI WebSocket, 33줄 "봇: 서버가 출발 시각·페이스를 내려 주고 각 폰이 계산"), `docs/api/realtime.md`

## 지금 (코드에서 확인)
- 앱으로 섬에 들어가면 섬의 봇 5명·무리 12명은 숨긴다(`AppRunBridge.HideIslandRunners`). 그래서 **지금 앱에는 봇이 하나도 없고** 서버 방의 사람만 보인다. 섬만 따로 Play할 때는 폰마다 따로 도는 `PaceSpeed`(③ 위반)
- 서버 방(`backend/app/realtime/hub.py`)은 사람만 있다. 방은 첫 사람이 붙을 때 생기고 다 나가면 사라진다
- 앱은 받은 `d`·`v`로 다음 값이 올 때까지 앞을 내다본다(`RemoteRunner`). 이름표·간격 카드·들어옴/나감 토스트는 원격 러너면 모두 같은 길로 간다
- "지금 N명"·입장 인원 검사는 DB 자리(`course_entries`)로 센다 → 봇은 원래 안 들어감

## 하는 것
1. **서버 봇**(`hub.py`, pytest): 방에 `Bot` 러너를 둔다. 위치는 서버 시계로 `d = (출발 위치 + 페이스 × (지금 − 출발 시각)) mod 코스 길이`이고, `welcome`·`states`를 만들 때 계산한다(배경 작업 없음). 메시지는 지금 러너 항목에 `bot: true`만 더한다. 사람이 들고 나면 정할 것 2대로 봇을 넣고 빼면서 `joined`·`left`를 보낸다. 방이 비면 봇도 같이 사라진다
2. **설정**(`core/config.py`): `.env`에 `BOT_FILL_TO`(목표 인원, 0이면 봇 없음)와 `BOT_PACES_KMH`(쉼표 목록)를 둔다. 잘못된 값이면 서버가 켜질 때 `ConfigError`(지금 `OCR_ENGINE`과 같은 방식). 오라클 `.env`에도 넣는다
3. **앱**: `RunTogetherRoom`이 `bot`을 읽어 `RemoteRunner.IsBot`에 넣는다. 섬 몸은 `RunnerTag.Kind.Bot`으로 두고 이름표에 "봇" 배지를 단다. 봇의 들어옴·나감 토스트는 안 띄운다. 간격 카드·입장 위치는 정할 것 4대로
4. **문서**: `docs/api/realtime.md`(메시지 표에 `bot`, 봇 규칙 절), ADR-0010 보충 한 줄(정할 것 1), `docs/unity/unity_map.md`
5. **확인**: pytest(봇이 생기고 빠짐, 같은 시각에 두 연결이 받은 봇 `d`가 같음, 사람이 늘면 봇 `left`, `BOT_FILL_TO=0`이면 봇 없음, 코스 바퀴 넘김). 에디터 Play + `fake_runner` 관찰 스크립트 둘로 같은 봇 위치를 시각과 함께 비교. 오라클 배포 뒤 아이폰과 에디터 두 화면에서 같은 봇이 같은 자리에 있는지

## 정할 것
1. **봇 위치를 어떻게 보낼지**: (가) **서버가 `d`·`v`를 계산해 사람과 같은 `states`에 실음** **(추천: 봇 속도가 일정해서 폰의 지금 내다보기(`d + v × 지난 시간`)가 출발 시각으로 직접 계산하는 것과 같은 자리를 낸다. 새 메시지나 서버 시각 맞추기가 필요 없고 앱 변경이 가장 작다. 대가는 봇 한 명당 초당 2번 약 40바이트)** vs (나) ADR-0010 33줄 그대로 출발 시각·페이스만 한 번 보내고 폰이 서버 시각(`pong`)으로 계산(메시지가 적은 대신 새 메시지 종류와 시계 맞추기를 앱에 새로 만들어야 함). (가)로 하면 ADR-0010에 "같은 위치라는 목표는 같고, 전달은 states로" 보충
2. **봇 수**: (가) **사람 + 봇 = 목표 인원(기본 6)** — 사람이 들어오면 봇 하나를 빼고 나가면 다시 넣는다. 사람이 6명 이상이면 봇 0 **(추천: 0029 메모 ⑤, 혼자 들어와도 섬이 비어 보이지 않음)** vs (나) 맵마다 고정 수(사람이 많아도 봇이 남음)
3. **기본 페이스·이름**(가설, 설정값이라 나중에 바꿈): (가) **5명 = 6·7.5·9·10.5·12 km/h, 이름은 "페이스 10:00"처럼 1km 페이스** **(추천: 걷기에 가까운 6부터 빠른 12까지 고르게. 이름이 곧 따라갈 기준이 됨. 문구는 상준 확인)** vs (나) 사람 이름처럼 보이는 닉네임 + 봇 배지
4. **간격 카드·입장 위치에 봇을 넣을지**: (가) **간격 카드엔 넣고(앞뒤 가장 가까운 러너에 봇도), 입장 위치는 사람만 기준**(사람이 없으면 지금처럼 랜덤) **(추천: 혼자일 때도 따라갈 대상이 생기고, 입장은 "같이 뛸 사람 뒤"라는 BL-25 ② 뜻을 지킴)** vs (나) 둘 다 사람만
5. **맵마다 다른 설정**(①): (가) **이번엔 모든 맵이 같은 `.env` 값**, 맵마다 다르게 하는 건 새 맵(BL-43)과 같이 `courses` 표에 칸 추가 **(추천: 지금 맵이 섬 하나의 코스 몇 개뿐)** vs (나) 지금 DB 칸

## 인원 세기 규칙 (11/17 민재 결정)
- **고스트(각자의 지난 기록)는 맵에서 뛰는 인원에 넣지 않는다**: 봇을 채우는 기준(정할 것 2의 "사람 수"), "지금 N명"(`runnersNow`), 맵 최대 20명 입장 검사 모두에서 뺀다. 고스트는 그 사람의 폰에만 보이는 것이라 같은 맵의 다른 사람과 상관없다
- 지금 코드도 그렇다: 인원은 DB 자리(`course_entries`)와 실시간 방의 사람만 세고, 고스트는 서버 방에 없다. 지환이 고스트(BL-24, S7)를 만들 때 서버 방(`hub`)에 러너로 넣지 않는다 → `docs/api/realtime.md` "인원" 절에 같이 적고 지환에게 알림
- 봇도 "지금 N명"·20명 검사에는 안 들어간다(사람만 셈). 봇은 빈자리를 채우는 것이라 사람이 들어오면 빠진다

## 안 하는 것
- 봇 속도 흔들기(섬 `PaceSpeed`의 ±0.25 km/h): 일정 속도로 시작하고, 어색하면 서버에서 같은 식으로 흔든다(모두에게 같음)
- 섬만 따로 Play할 때의 `PaceSpeed` 봇·무리: 앱 흐름엔 안 나와서 그대로 둔다
- 고스트(BL-24, 지환 S7)
