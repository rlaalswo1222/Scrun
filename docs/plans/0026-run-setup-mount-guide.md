## 흐름 (Figma 노트 그대로)
C-02 "맵 입장" → I-10 로딩·입장(`POST /entries`) → **맵 위에 D-01 러닝 설정 → D-05 거치 안내 → D-06 달리는 매뉴얼** → D-07 센서 준비(S3). 세 화면 모두 가로이고 흐린 맵이 배경이다. 보정이 없으면 지금처럼 보정(민재 #33)을 마친 뒤 다시 입장해서 D-01부터 시작한다.

## 하는 것
1. **겹쳐 뜨는 화면 자리**: `MapScreen` 안에서 입장이 끝나면 `RunSetupView`(순서는 `RunSetupSteps`)가 D-01 → D-05 → D-06 패널을 차례로 띄운다. 패널은 새 화면(Navigator)이 아니라 맵 화면 안의 층이다. 섬 씬과 입장 자리를 그대로 쓰므로 다시 불러오지 않는다. 뒤로 가기(버튼·Esc)는 한 단계 앞으로 가고, D-01에서 뒤로 가거나 오른쪽 위 X를 누르면 지금의 맵 나가기(→ C-02)와 같은 길로 간다
2. **배경 흐림**: 맵 카메라로 한 장 작게 찍어(화면의 1/4) 반씩 세 번 줄인 뒤(1/32) 크게 늘리면 흐리게 보인다. 그 위에 Figma의 Dim 색을 깐다. 안내가 떠 있는 동안 맵 카메라는 끄므로 아이폰 발열·배터리에도 좋다. 패널을 닫으면 카메라를 다시 켠다
3. **D-01 러닝 설정**
   - 위: "러닝 설정", 칩 "코스 이름 · 지금 N명"(C-02에서 받은 값)
   - 목표 카드: 거리/시간 탭, −/+ 버튼, 큰 숫자와 단위, 퀵 칩, "직접 입력"
     - 거리: 퀵 2·3·5 km(Figma), ± 0.5 km, 범위 0.5에서 42.2 km
     - 시간: 퀵 20·30·45분, ± 5분, 범위 5에서 180분
     - 직접 입력: 숫자 입력 시트(iOS 숫자 키보드), 범위를 벗어나면 이유를 밝히고 버튼을 막음
     - 처음 기본값은 거리 3 km(Figma), 그다음부터는 마지막으로 고른 목표(PlayerPrefs)
   - "이번 주 목표까지 N회 남았어요": `GET /users/me/weekly-goal`로 남은 횟수를 보여 준다. 목표가 없거나(`targetCount=null`), 이미 다 채웠거나, 불러오지 못하면 그 줄을 숨긴다(설정을 막지 않음). 이 API는 지금 예시 응답만 주고, DB 연결은 S6 BL-30
   - 고스트러너 카드는 S7까지 숨김(아래 정한 것 1)
   - "다음" → 고른 목표를 `RunSetup`(`Goal{type, value}`, 서버 단위 m·초)에 담아 D-05로. 서버에는 아직 보내지 않는다. `POST /runs`는 카운트다운이 끝날 때(S3 BL-11)
4. **D-05 거치 안내**: Figma 문구("폰을 러닝머신에 거치해 주세요", "화면이 정면으로 보이도록 가로로 세워 주세요"), 칩 "AirPods 착용 권장 (선택)", 오른쪽에 계기판 거치 그림, "거치했어요"(Figma 노트: 지금은 직접 확인 버튼. 자동 감지는 S3 센서 준비에서)
5. **D-06 달리는 매뉴얼**: 4단계 카드(그림 + Figma 문구 4개), "시작할게요". 아래에 **"다시 보지 않기"**(PRD ④ 💡)를 두고 켜면 다음부터 D-06을 건너뛴다(PlayerPrefs). D-05는 매번 보여 준다(달릴 때마다 거치해야 하므로). 다시 보는 길은 S7 마이·설정에 둔다
6. **D-06 다음**: D-07은 S3이므로 지금은 패널을 닫고 맵을 보여 주며, `RunSetup`을 S3 센서 준비·카운트다운이 받을 자리(`MapScreen.Setup`)에 남긴다
7. **모양**: `RunSetup.uxml`·`RunSetup.uss`를 UI Kit 값(App.uss 변수)으로. 카드·칩·탭·버튼은 Figma 컴포넌트(Chip/Default, Button/Primary)에 맞춘다. 상준에게 Figma와 나란히 확인을 요청한다
8. **테스트(EditMode)**: 목표 값 계산(±·범위 끝·km ↔ m, 분 ↔ 초), 퀵·직접 입력 검증, 마지막 목표 저장·불러오기, 남은 횟수 문구(null·0·음수), 단계 이동(뒤로 가기·건너뛰기)
