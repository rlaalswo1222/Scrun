## 앱에서 방식 바꾸기 (11/19 민재 요청, 승인: 개발 빌드에서만·세 방식)
헬스장 기록 전에 민재가 직접 달려 보며 비교할 수 있게, 마이 탭에서 달리기 속도 방식을 고른다
- **방식**: 기본(지금 앱) / 섞기(지금 앱 50% + 걸음 수 × 보폭 50%, 발 닿는 시간 = 폰 걸음 시간 − 에어팟 공중) / 섞기 + 치우침 고치기(60초). 셋을 **매 틱 모두 계산**하고 고른 것만 화면·아바타에 → 한 번 달리면 셋 값이 다 남음
- **Swift** `SpeedEstimator.swift`·`ScrunSpeed.swift`: 에어팟 중력을 따로 받음(지금은 더해서 넘겨 수직을 못 구함) → 수직 50 Hz로 걸음마다 공중 시간(계획 0012 규칙: 착지 0.2 g 위로, 발 떼기 0.3 g 아래로, 치우침 −2·−16 ms)을 실시간으로. 보정점에 `fl`(공중 ms) 추가, 보폭 기울기는 달리기 보정점으로 맞춤. 새 C 함수 `scrun_speed_set_method`. 걷기·에어팟 없음·`fl` 없는 옛 보정이면 기본 방식으로(스위치에 "다시 보정하면 쓸 수 있어요")
- **Python** `fusion_live.py`도 똑같이(기준 구현), 정답 파일 다시 만듦 → 맥 `SpeedReplay`로 Swift와 같은지(맥 할 일)
- **C#**: `CalibrationPoint.fl`(없어도 됨, 버전 1 그대로·옛 보정 호환), `ISpeedNativeApi.SetMethod`, 설정은 PlayerPrefs `scrun.speed.method`. 서버는 보정 모델을 JSON 통째로 저장해서 마이그레이션 없음. 달리기 중 개발 오버레이(`RunHudView`)에 세 값을 같이
- **마이 탭**: `MyScreen` 메뉴에 "속도 계산 방식(실험)" 줄 → 세 가지 중 고르기
- **확인**: pytest(재생 정답·옛 보정 호환), EditMode(설정 저장·옛 보정 파싱), `/code-review`, 아이폰은 맥에서 빌드해 민재가 달려 봄
