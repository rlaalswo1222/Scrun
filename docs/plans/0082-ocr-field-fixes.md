## 한 것
1. **km 소수 셋째 자리**: `NUM`·`NUM_IN_TEXT`에 `\d{1,3}\.\d{3}`, `parse_km`이 소수 셋째 자리까지("0.018" → 18 m). 시간 해석(`parse_time`)은 그대로라 "0.018"이 시간이 되지 않음
2. **콜론 없는 시간**: `parse_time(s, plain_ok)` — "0042" = 0:42, "024" = 0:24. **7세그먼트와 인식 글자가 같은 숫자열일 때만**(`Region.agree`). 꺼진 자리 "8888"(인식은 "AAAB")이 시간이 되는 것을 막음. 형식 규칙(라벨 없는 계기판)에는 안 씀
3. **낱말 막기**: 인식 글자가 낱말(글자 3개 이상, 숫자 없음, 인식 점수 ≥ 0.8 = `WORD_SCORE`)이면 7세그먼트를 돌리지 않음. 실사진 약 200영역에서 진짜 낱말은 0.84–1.0, 빨간 LED 숫자를 글자로 잘못 읽은 것("AFO" = 1.00, "AELDA")은 0.31–0.72 → 유일하게 맞게 읽은 p17이 그대로 삶
4. 테스트(`test_console_field`): 소수 셋째 자리, 콜론 없는 시간은 두 읽기가 같을 때만 READ(한쪽만이면 UNREADABLE), "8888"·초 60 이상 거부, 낱말 판단 6가지(TOTAL STEPS·프로그램·DRAX는 낱말, AFO·EQI3·점수 0.79는 아님). "12.345"는 이제 통째로 숫자(소수 셋째 자리), "12.3456"은 여전히 안 읽음
