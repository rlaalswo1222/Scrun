# 계획 0052: 앱이 꺼진 뒤 달리기 복구 — 복구 안내(I-04)·종료 요약(E-01) (BL-37)

- 상태: **승인(11/19 민재: 정할 것 1·2·3·4 모두 가)** · 구현 완료(에디터 확인 끝, 아이폰 확인·Figma 문구 남음)
- 담당: 민재(S8 [FE] 앱 종료 후 세션 복구, 노션 작업 표 BL-37). 0053·0054는 지환이 먼저 써서 이 번호는 비워 둠
- 왜: 달리는 중 앱이 꺼지면(강제 종료·메모리 부족·배터리) 다시 켜도 아무 안내가 없다. 서버 기록은 ACTIVE로 남고, 그 러닝은 기록 탭에도 결과에도 안 나온다
- 근거:
  - 노션 개발 백로그 "앱 종료 후 세션 복구": ① 다시 켜면 중단된 러닝을 알아챈다 ② 복구한 뒤 인증하거나 버릴 수 있다 ③ 복구 가능 시간은 앱 종료 후 24시간(11/06 확정)
  - 작업 표 BL-37 완료 확인: "달리는 중 앱을 강제 종료하고 다시 켜면 복구 안내가 뜨고 기록이 남아 있다"
  - 서버는 있음(#52, 계획 0037): `GET /runs/active`는 마지막 갱신 뒤 24시간 안에, 가장 최근에 시작한 ACTIVE 러닝 하나를 준다(거리·시간은 올라온 시계열로 셈). `POST /runs/{id}/discard`는 ACTIVE를 DISCARDED로 바꾼다
  - Figma I-04·E-01은 **아직 못 읽음**(11/19 Chrome에서 SCRUN 파일이 최근 항목으로 튕김, 접근 확인 필요). 구현 첫 단계에서 읽고 다른 점을 "진행"에 적는다
- 지금 코드(11/19 확인):
  - 달리는 동안 **폰에 저장되는 것이 없다**. `RunSession`은 메모리에만 있고, 폰에 남는 것(`PendingRunStore`, `pending-runs.json`)은 종료를 눌렀는데 보내기에 실패했을 때만 쓴다
  - 서버에는 시계열이 60초 묶음으로만 올라간다(`RunRecordUploader.ChunkSamples`). 꺼지면 마지막 1분 안쪽은 사라진다
  - 출발 신호(`POST /runs`)를 15초 동안 못 보냈으면 runId가 없다. 그러면 시계열도 안 올라가서, 꺼지면 서버에도 아무것도 없다
  - 앱 쪽에는 `active`·`discard` 호출도, 앱이 백그라운드로 가거나 꺼질 때 하는 처리도 없다. 홈에 올 때 `HomeScreen.OnShow`가 남긴 기록을 보내는 것만 있다
  - `VerifyScreen`은 runId만 있으면 된다. 센서 값은 에디터 가짜 OCR 이름에만 쓴다. 다만 서버에서 기록이 먼저 끝나 있어야 한다(ACTIVE면 `finish`부터)

## 흐름
```
앱을 켬 → 홈(처음 한 번) → 폰에 남은 진행 기록 or GET /runs/active
  └ 있으면 I-04 "끝나지 않은 러닝이 있어요"(코스·시작 시각·거리·시간)
       ├ "마무리하기" → 남은 시계열 + finish(종료 = 마지막으로 기록된 시각) → E-01 종료 요약
       │     ├ 서버가 인증 대기로 끝냄(멈춘 뒤 10분 안): "계기판 촬영하기" → E-02 인증(지금 VerifyScreen) → E-11·E-12 / "촬영 없이 마무리" → E-14
       │     └ 서버가 바로 미인증(10분 넘음): 촬영 버튼 없이 "결과 보기" → E-14 (정할 것 2)
       └ "버리기" → 확인("기록이 지워져요") → discard → 홈
```

## 하는 것
1. **폰에 진행 기록 남기기**(정할 것 1 가): `ActiveRunStore`(`active-run.json`, 사용자별)
   - 남기는 것: 출발 본문(clientRunId·코스·목표·고스트), runId(받으면), 달린 시간, 거리, 1초 시계열, 마지막 기록 시각
   - 언제 쓰나: 출발할 때, 5초마다, 일시정지·백그라운드로 갈 때(`OnApplicationPause`)
   - 언제 지우나: 정상 종료 때(그 뒤는 지금처럼 `PendingRunStore`가 맡음), 버리기
   - 파일이 깨지면 무시하고 서버 `active`만 본다
2. **알아채기**: 앱을 켠 뒤 홈에 처음 왔을 때 한 번 확인한다
   - 폰 기록이 있으면 그것을 쓴다. 서버 `active`와 runId가 같으면 폰 쪽이 더 정확하다(마지막 1분 포함)
   - 폰 기록이 없으면 `GET /runs/active`를 본다(앱을 지우고 다시 깐 경우 등)
   - 마지막 기록 뒤 24시간이 지났으면 묻지 않고 폰 기록을 지운다(서버 기준과 같게)
   - 남의 계정이 남긴 기록은 건드리지 않는다
   - 남긴 기록 보내기(`FlushPendingRuns`)보다 먼저 한다
3. **I-04 복구 안내**(홈 위 시트 또는 화면, Figma 확인 뒤 정함): 코스 이름·시작 시각·거리·시간, "마무리하기"·"버리기"(확인 한 번 더)
4. **마무리**: `RunRecordUploader`의 보내기를 다시 쓴다(runId가 없으면 출발부터 → 남은 묶음 → `finish`). 종료 시각은 마지막 기록 시각, 거리·시간은 폰 기록 값(서버만 있으면 `active`의 값). 못 보내면 지금처럼 `PendingRunStore`에 남기고 E-14 간이 결과(`RunResultScreen.Offline`과 같은 방식)
5. **E-01 종료 요약·인증 전**: 거리·시간 카드와 인증 안내. D-22(`RunEndView`)와 같은 버튼 규칙이다(저장돼야 촬영, 저장 중이면 기다림). 촬영하면 `VerifyScreen(runId, sensor, …)`, 끝나면 지금 결과 흐름 그대로(`AfterVerify`). 복구 흐름은 탭 화면 위에 쌓인다(맵을 거치지 않음)
6. **서버(작게, 마이그레이션 없음)**:
   - `GET /runs/active`에 `lastActiveAt`(마지막 갱신 시각)을 더한다. 폰 기록이 없을 때 종료 시각으로 쓴다
   - 인증 마감 규칙(정할 것 2 가, 리뷰 뒤 바꿈): 앱이 `finish`에 `sentAt`(보낸 시각, 폰 시계)을 싣는다. 서버는 `sentAt − endedAt`(둘 다 폰 시계라 폰 시계가 틀려도 차이는 맞음)이 10분 이하면 받은 시각 + 10분 마감, 넘으면 바로 닫아 응답부터 미인증. `sentAt`이 없는 옛 앱은 지금처럼 받은 시각 + 10분. 처음 안(`min(받은 시각, 종료 + 10분) + 10분`)은 서버 시계와 폰 시계를 섞어서, 폰 시계가 20분 넘게 늦으면 방금 끝낸 러닝도 닫혔다
7. **확인**:
   - EditMode: 진행 기록 저장·읽기·깨진 파일·사용자별, 24시간, 폰 기록과 서버 `active` 중 고르기, 10분 판정
   - pytest: `lastActiveAt`, 마감 규칙(바로 끝냄은 10분 / 2시간 전 종료는 닫힘)
   - 에디터 Play(로컬 서버): 달리다가 Play를 멈춤(강제 종료 대신) → 다시 Play → I-04 → 각 갈래(촬영·촬영 없이·버리기·runId 없이 꺼짐)
   - 아이폰: 앱 전환기에서 위로 밀어 끄기 → 다시 켜기(노션 공통 아이폰 확인에 줄 추가)
