# 0017 기능 분담·스프린트 계획 (11/08–11/23)

- 상태: **승인·노션 반영** (2026-11-07 민재 승인 → 같은 날 노션 [개발 계획](https://app.notion.com/p/4114ae82f1de81a9bec2db16a9bfe635): 기능 보드 20개, 작업 표 80줄)
- 담당: 민재(리드)
- 원본 백로그: 상준 공개 개발 백로그 51개(BL 번호). 이 계획은 BL을 지우거나 고치지 않고, 기능 묶음·담당·스프린트만 붙인다

## 왜
- 처음엔 상준이 화면을 전부 만들 생각이었다. 그런데 화면이 많고(Figma 94개) 와이어프레임도 아직 끝나지 않았다. 그래서 **민재·지환이 기능 단위로 화면부터 서버까지 끝까지 맡는다**(11/07 민재 결정)
- 상준은 **UI Kit·공통 스타일(USS)**과 와이어프레임 마무리를 맡는다. 각 화면의 UXML과 동작은 그 기능 담당이 키트를 써서 만들고, 상준은 다 만든 화면의 모양을 다듬고 테스트한다
- 목표: 11/23까지 F01–F10 기능 완성, 11/24–12/10 안정화, 12/11 발표. 스프린트는 2일 단위로, 끝날 때마다 아이폰에서 돌아가는 것을 확인한다

## 담당 원칙
- 민재: 원래 맡던 속도·달리기 화면·보정·실시간·서버에 더해 로그인·온보딩·친구
- 지환: 원래 맡던 3D·맵·OCR·고스트에 더해 코스 선택·러닝 설정·계기판 인증·기록·목표/홈·마이
- 서버 API는 그 기능 담당이 DB와 연결한다(지금은 로그인 5개 외에는 예시 응답만 주는 스텁). 서버 공통(DB 구조, 인증, 배포)은 민재가 맡고 PR 리뷰도 민재가 한다
- 노션 작업 표에서는 BL마다 [FE] 화면·동작(아이폰 기능을 부르는 Swift 코드는 [FE·Swift], Xcode·실기기 필요), [BE] API, [3D], [디자인] 줄로 나눈다
