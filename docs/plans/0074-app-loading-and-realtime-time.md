# 계획 0074: 앱 로딩 체감 줄이기 + 같이 뛰기 상대 위치를 서버 시각으로

- 상태: **승인**(2026-11-26 민재 "다 추천대로"). 로딩(1)과 시각 보정(2)을 같이, 스켈레톤 늦게 띄우기는 뺌
- 담당: 민재(앱 + 서버 실시간 한 줄)
- 왜
  - **로딩**(11/25 분석, 인수인계): 기록·친구 첫 로딩은 서버 처리 5–18 ms뿐이고 나머지는 싱가포르 왕복 약 95 ms(가끔 225)·새 연결 0.28–0.68초·토큰 1시간 만료 뒤 재발급 왕복. 앱이 받은 데이터를 기기에 저장하지 않아 **앱을 켤 때마다 탭 첫 진입에 스켈레톤**(같은 실행 안에서는 탭 화면을 보관해 조용히 새로 받음)
  - **시각**: `RemoteRunner`는 값을 **받은 순간**부터 v × 시간으로 내다봄([RemoteRunner.cs](../../unity/TestRun/Assets/Scrun/App/Realtime/RemoteRunner.cs)). 받은 값은 이미 (상대 폰 → 서버) + (서버가 0.5초마다 모아 보냄, 평균 0.25초) + (서버 → 내 폰)만큼 묵은 값이라 **상대가 그만큼 뒤에 보임**: 평균 0.35–0.47초 × 10 km/h ≈ 1–1.3 m(계산, 가설). 서버 `states`에는 보낸 시각(`serverTime`)만 있고 러너별로 그 값을 언제 받았는지는 없음
- 결과물: 앱을 다시 켜도 탭이 **바로 지난 데이터로** 보이고 뒤에서 조용히 새로 받음. 같이 뛰기에서 상대가 **실제 위치에 가깝게** 보임

## 하는 것
### 1. 로딩 (앱)
- **A. 마지막 응답 캐시 → 먼저 보이기**(캐시 = 서버에서 마지막으로 받은 응답을 폰에 파일로 남겨 둔 것): 홈·기록·친구(목록·달리는 친구·피드)·마이의 첫 페이지 응답을 사용자별로 기기에 저장(`Application.persistentDataPath`, 앱 안에서만 읽힘). 켤 때 캐시으로 바로 그리고 뒤에서 새로 받아 바뀐 곳만 갱신(지금 같은 실행 안에서 하는 방식을 앱을 다시 켤 때까지 넓힘). 캐시이 없을 때(설치 직후)만 스켈레톤 — 기다리는 중이 맞으니 바로 보임
  - 버리는 때: 러닝 종료·인증·친구 추가·삭제·설정 바꿈 직후(그 탭은 새로 받을 때까지 캐시을 안 씀), 로그아웃·계정 삭제(전부 지움), 앱 버전이 바뀜(응답 모양이 달라질 수 있음), 오래됨(예: 7일)
  - 개인정보: 기록·친구 닉네임이 기기에 남음 → iOS 파일 보호(기기 잠금 중 못 읽음) 켜고 개인정보처리방침에 한 줄(상준, BL-40)
- **B. 탭 데이터 미리 받기**: 홈을 그린 뒤 기록·친구 첫 페이지를 뒤에서 받아 둠(캐시이 없을 때 탭 전환이 바로). 동시에 2개까지, 셀룰러에서도(응답이 작음, 확인)
- **D. 토큰 미리 갱신**: 로그인·재발급 응답의 `expiresInS`로 만료 시각을 기억해, 앱으로 돌아올 때(`OnApplicationPause(false)`)·요청 직전에 5분 안에 만료면 먼저 재발급(지금은 401을 받은 뒤 재발급 → 왕복이 하나 더). 재발급은 이미 한 번만 돌게 묶여 있음(`ApiClient.RefreshAsync`)
- ~~C. 스켈레톤 늦게 띄우기~~ → **뺌**(11/26 민재·Claude): 이득은 0.3초 안에 오는 응답뿐인데 새 연결이면 넘기기 쉽고(가설), 빈 화면 → 스켈레톤 → 내용으로 두 번 바뀌어 덜컹거림. A를 하면 스켈레톤이 거의 안 떠서 이유가 없어짐

### 2. 같이 뛰기 시각 (서버 한 줄 + 앱)
- 서버: `states`·`welcome`의 러너마다 **그 값을 서버가 받은 시각** `at`(ms, 서버 시계) 추가. 봇은 `states`를 만든 시각(계산값이라 지금 위치). 옛 앱은 안 읽으니 그대로 됨
- 앱: `RemoteRunner.Sample`의 기준 시각을 "받은 순간" 대신 `at`을 내 시계로 바꾼 값(`at − ServerOffsetMs`, 이미 `pong`으로 잼)에 상대 폰 → 서버 몫(내 왕복의 절반으로 어림, 가설)을 뺀 값으로. `ServerOffsetMs`가 아직 없으면(첫 `pong` 전) 지금처럼
- 확인: 앱 단위 테스트(묵은 값이 그만큼 앞에서 보임, 시계가 틀어져도 상한), 서버 테스트(`at`), 아이폰 2대 헬스장 실측(보이는 간격·`RoundTripMs`) → `docs/api/realtime.md` "지연 실측" 칸

## 정할 것
1. 저장할 화면: 홈·기록·친구·마이 첫 페이지(추천) / 홈만
2. 캐시 수명: 7일(추천, 더 오래면 캐시 없이 스켈레톤)
3. 미리 받기를 셀룰러에서도(추천: 예, 응답이 작음 — 크기 잼)
4. 상대 폰 → 서버 몫 어림: 내 왕복의 절반(추천, 상대 왕복은 모름) / 서버가 상대의 마지막 왕복을 같이 보냄(정확하지만 메시지가 커짐)
