# 계획 0047: S8 같이 달리기 — 친구 근처에서 시작 (BL-29)

- 상태: **승인(11/18 민재: 정할 것 1·2·3 모두 가)** · 구현 중
- 담당: 민재(서버 API·앱 연결, 역할 0017 "실시간 공동 맵·친구"). 시트·D-20·D-21 문구와 모양은 상준 확인
- 왜: S7(계획 0044 정할 것 4 가)은 G-03 "같이 달리기"를 눌러도 그 코스로 **일반 입장**만 함 → 친구와 같은 맵이긴 해도 코스 아무 데서나(달리는 사람 한 명의 20–40m 뒤, 친구가 아닐 수 있음) 시작. `POST /friends/{userId}/run-together`는 아직 예시 응답
- 지금 있는 것: 일반 입장 `POST /courses/{courseId}/entries`(보정·가득 참 검사, 자리 잡기, 실시간 토큰), 실시간 `welcome`·`states`(방 안 사람들의 지금 `d`), 친구 판정 `_require_friend`, 달리는 친구 `hub.running_now`, 앱 G-03 시트 → `CourseDetailScreen(enterOnLoad)`

## 흐름
```
G-03 "같이 달리기" → POST /friends/{userId}/run-together
  ├ 201 MapEntry + friendUserId  → 섬 불러오기 → 실시간 welcome에서 친구의 지금 d → 친구 뒤 N m에 섬(정할 것 1·2)
  ├ 409 FRIEND_NOT_RUNNING(그새 끝냄) → D-21 안내 → 그 코스로 일반 입장(지금 S7 흐름)
  └ 404 친구 아님 · 409 COURSE_FULL · CALIBRATION_REQUIRED → 일반 입장과 같은 화면
```

## 하는 것
1. 서버 `run-together` DB 연결: 친구인지(아니면 `USER_NOT_FOUND`, 프로필 API와 같게) → `hub.running_now`로 달리는 중인지·코스(아니면 `FRIEND_NOT_RUNNING`) → **일반 입장과 같은 함수로** 보정·가득 참 검사·자리 잡기·실시간 토큰(코드 두 벌 안 만듦) → 입장 위치는 친구의 지금 위치 기준. 응답은 `MapEntry` + `friendUserId`(새 칸, 일반 입장은 null)
2. 앱: G-03 확인 → `run-together` 호출, 실패 코드별 처리(위 흐름), 시트 끝 문장 "친구 근처에서 시작해요." 켜기. 섬이 다 열린 뒤 첫 `state` 전에 친구 위치로 다시 맞춤(정할 것 2)
3. 테스트: 서버(친구 아님·안 달림·가득 참·보정 없음·위치·같은 요청 두 번), EditMode(흐름·위치 다시 맞추기), 에디터 Play(`fake_runner --kakao k_911`로 친구를 달리게 하고 같이 달리기 → 친구 뒤에 서는지)
4. 문서: `docs/api/realtime.md`·`README.md`, `unity_map.md`, 노션 API 명세·작업 표

## 정할 것
1. **친구 뒤 몇 m에 설까**: (가) **10–20m 뒤 (추천, 가설: 화면 앞쪽에 친구가 바로 보이고 이름표가 안 겹침 → 아이폰에서 보고 조정)** vs (나) 일반 입장과 같은 20–40m 뒤
2. **언제의 친구 위치로**: (가) **섬을 다 불러온 뒤 실시간 `welcome`·`states`의 친구 `d`로 앱이 다시 맞춤 (추천: 섬을 불러오는 동안(가설 5–15초) 친구가 10 km/h면 15–40m 더 가서, 입장 응답 때 위치로는 친구가 멀리 앞에 있음. 실시간 메시지는 그대로라 서버·프로토콜 안 바뀜)** vs (나) 입장 응답의 위치 그대로
3. **친구가 섬을 불러오는 사이 끝냈을 때**(입장은 됐는데 `welcome`에 친구가 없음): (가) **그 자리(입장 응답 위치)에서 그냥 시작 + 토스트 "친구가 러닝을 마쳤어요" (추천: 이미 섬에 들어와 있어 되돌리면 더 번거로움)** vs (나) 맵을 나가 D-21
