# 계획 0053: 기록 탭 — 기록 목록(F-01)·빈 상태(F-02)·기록 상세(F-03·F-04) (BL-20)

- 상태: **승인(11/18 지환: 정할 것 1·2·3 모두 가)** · 구현(11/18, PR #94) · 민재 리뷰 반영(11/19) · 아이폰 확인 남음
- 담당: 지환(S5 [FE] 기록 목록·상세, 노션 작업 표 BL-20). 0052는 민재 세션 복구 몫이라 0053
- 왜: 아래 탭 "기록"이 아직 빈 자리(`PlaceholderScreen("기록", …)`). 결과 화면(E-12, #90)의 "기록 보기"는 숨겨 둠, 고스트(#87)의 "이 기록으로 고스트 달리기"는 갈 곳이 없음. 서버는 끝남: `GET /runs`(끝난 기록 최신순, 20개씩 커서, `month=YYYY-MM`은 내 시간대 달), `GET /runs/{id}`(#63·#90)
- 근거: 노션 작업 표 BL-20 "기록 탭: 월별 목록에 인증 상태, 상세에서 속도 변화 그래프, 기록이 없을 때 빈 화면. 삭제·수정은 없다", 완료 확인 "여러 번 달린 기록이 달별로 보이고 상세 그래프가 뜬다", 메모 "F-05 삭제 다이얼로그는 제외". Figma(11/18 읽음) F-01 "기록 · [11월][10월][전체] · 이번 주 3회 / 거리 8.9km / 인증 3/3 · 카드(날짜·거리·시간·평균 페이스·인증 칩) → F-03", F-02 "아직 기록이 없어요 · 첫 러닝을 마치고 계기판을 인증하면 여기에 기록이 쌓여요 → C-01", F-03 "‹ 기록 상세 · 날짜·인증 칩·큰 거리·시간·평균 페이스·종료·속도 변화·센서·계기판 대조 결과 보기 › · 이 기록으로 고스트 달리기(→ C-01 → D-02 고스트 미리 고름)", 노트 "구간별 정보·함께 달린 러너는 추후 검토", F-04 미인증 "미인증 기록은 주간 목표와 인증 마크에 반영되지 않아요"

## 흐름
```
기록 탭 → F-01 RecordsScreen ─ 달 칩(이번 달·지난 달·전체) → GET /runs?month=… ("더 보기"로 다음 쪽)
                             ├ 기록이 하나도 없음 → F-02 빈 상태 → "달리기 시작하기" → 홈 탭 C-01
                             └ 카드 → F-03·F-04 RunResultScreen(상세 모양) ─ "이 기록으로 고스트 달리기"
                                                                             → C-01 → 코스 상세 → 러닝 설정(고스트 켜짐 + 이 기록)
E-12 결과 "기록 보기" → 결과 화면들을 내리고 기록 탭
```

## 하는 것
1. `RecordsScreen`(새, 기록 탭 첫 화면, UXML `UI/Records`): 달 칩, 이번 주 요약 3칸(정할 것 1), 기록 카드(날짜 `FriendText.RunDate`·큰 거리·"시간 · 평균 페이스"·인증 칩 완료/미인증/인증 대기), "더 보기"로 `nextCursor` 다음 쪽(친구 피드·D-03 시트와 같게), 고른 달에 기록이 없으면 "11월에는 기록이 없어요"(전체가 비면 F-02). 탭에 다시 들어오면 `Feedback.Load(이미 보이는지, …)`로 조용히 새로 받음(#89)
2. 상세: 민재 `RunResultScreen(runId)`에 상세 모양(정할 것 2) — 뒤로 ‹·제목 "기록 상세", 닫기·"홈으로"·"기록 보기" 숨김, "이 기록으로 고스트 달리기" 버튼. 뒤로 → 목록
3. 고스트 연결(정할 것 3): 상세 → `CourseListScreen(ghost)` → `CourseDetailScreen(ghost)` → `RunSetupView`가 고스트 카드를 켜고 그 기록을 골라 둔 채로 시작(바꾸기·끄기는 그대로). 기록 탭 안에서 쌓음
4. E-12 "기록 보기" 켜기: 결과 화면들을 내리고 `SelectTab(Records)`
5. 순수 계산 `Run/RecordsText.cs`(EditMode): 달 칩 이름·`month` 값(이번 달·지난 달, 1월이면 지난해 12월), 이번 주 범위(월요일 0시, 폰 시간대)와 요약, 빈 달 문구
6. 확인: EditMode, 에디터 Play(로컬 서버, 에디터 계정의 인증 완료·미인증 기록으로 목록 → 상세 → 고스트 달리기 → 러닝 설정에 고스트가 골라져 있는지, 달 칩, 빈 상태는 새 계정), 문서 `unity_map.md`·계획 상태·handoff·노션 작업 표 BL-20

## 정할 것
1. **이번 주 요약 3칸**(서버에 요약 API 없음, 주간 목표 BL-30은 아직 예시 응답): (가) **앱이 목록 첫 쪽에서 셈. 이번 주 = 월요일 0시부터(폰 시간대), "이번 주 N회 · 거리(인증 완료 + 미인증 + 인증 대기 공식 거리 합, 대기는 마감 10분 안의 방금 기록) · 인증 N회". 주간 목표(BL-30)를 만들면 셋째 칸을 "인증 N/목표"로 바꿈 (추천: 서버를 안 고쳐도 되고, 한 주 기록은 거의 항상 첫 쪽 20개 안. 넘으면 다음 쪽까지 받음)** vs (나) 서버에 `GET /runs/summary`를 새로 만들어 주간 목표 주기(설정한 날부터 7일)와 맞춤 vs (다) 요약 칸을 빼고 BL-30 때 넣음
2. **기록 상세 모양**(Figma F-03은 E-12보다 적음: 공유·함께 달린 러너·목표가 없고 "종료 07:41"이 있음. 서버는 종료 시각을 안 줌): (가) **E-12 결과 화면 내용 그대로(목표·함께 달린 러너·피드 공유 토글 포함), 위만 ‹ 기록 상세, 아래는 고스트 버튼. 종료 칸은 목표 칸으로 (추천: 한 화면이라 고치는 곳이 하나, 공유는 나중에 상세에서 끄고 싶을 수 있음. 종료 시각은 서버를 고쳐야 하고 시작·시간으로 대신 알 수 있음)** vs (나) Figma F-03대로 공유·러너를 숨기고 서버에 종료 시각을 추가
3. **"이 기록으로 고스트 달리기" 갈 곳**: (가) **Figma대로 코스 목록(C-01) → 코스 상세 → 러닝 설정에 고스트가 켜진 채 (추천: 고스트는 코스와 상관없이 쓸 수 있어서 다른 섬 코스에서도 같이 달릴 수 있음)** vs (나) 그 기록을 달린 코스 상세로 바로
