# 계획 0008: 에어팟으로 공중 시간을 잴 수 있는지 제자리 뛰기로 확인

- 상태: **구현** (2026-10-29 승인. 10/29 제자리 뛰기 첫 시험(메트로놈 없음) + 러닝머신 14구간 1회(탐색), 분석 `speedlab/exp/airpods_flight.py`·`airpods_treadmill.py`, 결과 `docs/speed/airpods_flight.md`. 제자리 방법은 러닝머신에서 안 통함 → 러닝머신용 지표를 새 기록으로, 메트로놈 170 재시험 남음)
- 작성: 2026-10-29, 사용자 승인. 브랜치 `feat/airpods-flight`
- 왜: 걸음 수가 거의 그대로여도 빨라지면 발 닿는 시간이 줄고 공중 시간이 늘어난다(SoundTrackDB 재분석: 1 km/h당 발 닿는 시간 −15 ms, 공중 +12 ms, 정답 발 닿는 시간을 넣으면 오차 0.44 → 0.36, [soundtrackdb.md](../speed/soundtrackdb.md)). 폰은 착지 뒤 울림 때문에 발 떼는 순간을 못 봄 → 몸에 붙은 에어팟이 공중 시간을 잴 수 있는지가 관건. 에어팟 실측은 아직 없음(10/12 `data/runs/20261012-1544*`의 `airpods_acc.csv`는 `"device": "simulator"`). 에어팟은 약 25Hz(40 ms 간격)라 1 km/h에 해당하는 12 ms를 여러 걸음 평균으로 구분하는지 봐야 함

## 무엇을
1. SpeedRecorder(`ios/`): 에어팟 중력 방향 `airpods_grav` 기록 추가(지금은 중력 뺀 가속도만 저장), "제자리 뛰기" 구간 세트 버튼(가만히 서기 10초 → 점프 3번 → 낮게·보통·높게 각 30초 → 점프 3번)
2. 맥북에서 처음 빌드·아이폰 설치([ios/README.md](../../ios/README.md)). 노트북 `server.py`와 같은 와이파이
3. 실험: 에어팟 양쪽 착용. 아이폰은 두 손으로 가슴에 붙여 고정, 팔은 흔들지 않음(손에 느슨히 쥐면 팔 움직임이 섞여 공중에서도 0g가 안 됨). 걸음 수는 다른 기기 메트로놈 170 spm으로 고정 → 걸음 시간은 같고 공중 시간만 바뀜(러닝머신에서 속도 올릴 때와 같은 상황)
4. 분석 `speedlab/exp/airpods_flight.py`: 공중 = 몸 가속도 약 0g 구간. 에어팟(25Hz)과 아이폰(100Hz) 공중 시간의 30초 평균 비교, 높이 3단계 구분

## 판정
- 에어팟과 아이폰의 30초 평균 공중 시간 차이가 12 ms(1 km/h 해당)보다 작고, 낮게·보통·높게 순서대로 구분되면 → 러닝머신 실험에 에어팟 추가
- 안 되면 → 에어팟은 걸음 수·멈춤 감지용으로만

## 다음: 러닝머신에서 (10/29 사용자 결정, 집 시험은 1회로 마침)
- 집 시험 결론: 공중 동안 에어팟 신호는 깨끗하고 순서는 구분, 높게 구간의 흔들림은 가슴의 아이폰(정답) 쪽으로 보임. 독립 정답으로 정확도 확인은 안 됨([airpods_flight.md](../speed/airpods_flight.md))
- 헬스장: S22는 계기판 위 SpeedLab(충격), 아이폰 + 에어팟은 SpeedRecorder로 같은 속도 순서 기록(노트북 server.py + 아이폰 핫스팟). 구간 평균만 비교하므로 두 기기 시계는 초 단위로 충분
- 판정: 공중 시간이 1 km/h당 약 12 ms씩 늘어나는지(SoundTrackDB 기준), 충격에 더했을 때 검증 구간 오차가 줄어드는지
