# 계획 0077: 503 문구를 이유(`details.reason`)별로

- 상태: **완료**(2026-11-26, 민재 승인 "ㅇㅇ", EditMode 570 통과, 브랜치 `feat/503-reason-copy`). 원래 지환과 같이 하려던 것(0071 리뷰)을 민재가 다 하기로(11/26)
- 담당: 민재. 문구는 임시, 상준 확인
- 왜: 0071·0073 뒤로 서버 503에 이유가 붙음(`BUSY` 동시성 한도 초과, `DB_BUSY` DB 연결 못 받음, `OCR_TIMEOUT` 읽기 시간 초과, `REALTIME_BUSY` 맵 입장 때 실시간이 바쁨). 앱 인증 화면은 `OCR_TIMEOUT`만 가르고 나머지는 모두 "계기판을 읽는 곳이 바빠요" → 서버 전체가 붐빌 때도 계기판 탓처럼 보임. 다른 화면은 서버 기본 문구 "서버를 잠시 쓸 수 없습니다."

## 서버가 어디서 무엇을 보내나 (코드 확인)
| 요청 | 503 이유 |
|---|---|
| 사진 보내기(`ocr` 프로세스) | `BUSY`·`DB_BUSY`·`OCR_TIMEOUT`, 이유 없음 = OCR 쪽(읽기 대기열 가득·엔진 고장·준비 안 됨) |
| 읽은 값 확인·미인증 저장·그 밖 모든 API(`api`) | `BUSY`·`DB_BUSY` |
| 맵 입장 | 위 + `REALTIME_BUSY`(서버 문구 "맵 인원을 확인하지 못했습니다. 잠시 뒤 다시 들어가 주세요." 그대로 보임 → 안 바꿈) |

## 하는 것 (앱만, 서버 배포 없음)
1. `ApiException`에 `Reason`(`DetailsJson`의 `reason`) 읽기 하나 → 인증 화면 `IsOcrTimeout`의 문자열 찾기도 이걸로
2. **인증 화면 사진 보내기 실패(503, `OCR_TIMEOUT` 빼고)**: "계기판을 읽는 곳이 바빠요. 잠시 뒤 다시 보내 주세요." → **"사진 확인이 잠시 안 돼요. 그대로 다시 보내 주세요."**(11/26 민재 고름). 붐빔(`BUSY`·`DB_BUSY`)이든 OCR 쪽(이유 없음)이든 할 일이 같아 하나로. `OCR_TIMEOUT`은 지금처럼 다시 찍기 안내
3. 공통 안내(`Feedback.Describe`): 503 + `BUSY`·`DB_BUSY`면 본문을 서버 기본 문구("서버를 잠시 쓸 수 없습니다.") 대신 **"지금 이용하는 사람이 많아요."**(제목이 이미 "잠시 후 다시 시도해 주세요"라 같은 말은 뺌, 리뷰). 보이는 곳: 공통 안내창(`Feedback.Handle`)·미인증 저장 실패·맵 입장 실패. **화면 첫 로딩 실패(홈·기록 등 `StateView`)는 Figma I-09 고정 문구 그대로**(다시 시도할 수 있는 실패는 원래 서버 문구를 안 씀, 할 일이 같아 안 바꿈 — 11/26 민재). 읽은 값 확인 실패는 지금 문구("잠시 뒤 다시 눌러 주세요.") 그대로
4. EditMode 테스트: 이유 읽기(없음·글자 아님·배열·깨진 JSON), 붐빔 판정, 공통 안내 문구, 인증 화면에서 503 이유별 오류 종류(`ErrorOf`)와 그때 문구(`SendErrorText`)

## 안 하는 것
- `Retry-After`를 따라 자동으로 다시 보내기(진짜 백프레셔) → 따로
- 서버 이유 더 나누기(OCR 대기열 가득 `OCR_BUSY` 등): 이유 없음 = OCR 쪽으로 충분해서 이번엔 안 함
- 서버가 꺼져 Caddy가 빈 본문·HTML로 502/503을 줄 때(배포 중 등): 앱은 응답을 못 읽음(`BadResponse`)으로 처리해 인증 화면 "사진을 보내지 못했어요", 공통 안내 "서버 응답을 읽지 못했어요." — 전과 같음(리뷰에서 나옴, 따로)

## 리뷰 반영 (11/26, `/code-review` 규칙·스펙 두 축)
- 편집 도구가 지운 `TimeoutText` 줄 공백 되돌림(상관없는 줄이 diff에 끼지 않게), 낡은 주석 두 곳("바빠요")·`Feedback.cs` 주석 자리
- 붐빔 본문에서 제목과 겹치는 말 뺌, 앱이 안 쓰는 `REALTIME_BUSY` 상수 뺌
- 테스트를 상수 비교에서 실제 동작으로: `ErrorOf`·`SendErrorText`를 `internal`로 열어 이유별로 확인, 인증 화면 테스트는 `VerifyScreenTests`로, 503 도우미 하나로
- 위 3번 "모든 화면에 적용"이 사실과 달라(첫 로딩 실패는 I-09) 계획 문장을 고침
