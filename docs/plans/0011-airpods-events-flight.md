# 계획 0011: 귀 센서 논문 방식(착지·발 떼기 순간)으로 에어팟 공중 시간 다시 재기

- 상태: **완료** (2026-10-29 사용자 "해봐" → 같은 날 분석). 브랜치 `feat/airpods-treadmill`, PC 분석만(새 실험 없음)
  - 고정한 방법(순간 찾기)은 **실패**: 발 떼기가 디딤 봉우리 바로 뒤에 잡혀 공중 210 ms·발 닿는 시간 145 ms(거꾸로), 걷기에도 공중 340 ms → 속도와 반대로 감
  - 그림을 보고 한 **추가 탐색**: 0.3 g 기준을 크기 대신 수직에 → 걷기 0 ms, 달리기에서 속도 따라감(B·M 둘 다). 결과 [airpods_flight.md](../speed/airpods_flight.md) 끝 절
- 왜: 문턱값(전체 가속도 0.3 g 아래 = 공중) 방식은 러닝머신에서 실패([airpods_flight.md](../speed/airpods_flight.md)). Stuchbury-Wass 외(J Appl Biomech 2026, 귀 50 Hz, 30명)는 순간을 찾는 방식으로 걸음마다 공중 시간 오차 11.9 ms를 보고([treadmill_sensing_papers.md](../research/treadmill_sensing_papers.md)). 같은 방식이 에어팟에서 속도를 따라가는지 확인

## 방법 (결과 보기 전에 고정, `speedlab/exp/airpods_events.py`)
1. 수직 가속도 = 에어팟 가속도(중력 뺀 값)를 중력 방향(`airpods_grav`)에 투영, 위쪽 +, g 단위. 끊김(0.15초 넘는 틈)으로 조각 나눔, 조각마다 50 Hz 고르게 다시 뽑기
2. 걸음 = 수직 가속도의 큰 봉우리(디딤 가운데). 간격은 자기상관 걸음 주기의 0.6배 이상
3. 착지 = 그 봉우리 앞 0.15초 안에서 수직 가속도 2차 미분의 최댓값(충격 봉우리 시작). 발 떼기 = 10 Hz 저역 필터 → 저크 → 저크 미분의 최솟값, 봉우리 뒤 0.25초 안. 극값 자리는 포물선 보간으로 샘플 사이까지
4. 공중 = 다음 착지 − 발 떼기, 5 ms에서 0.5초만. 구간마다 중앙값. 발 닿는 시간 = 발 떼기 − 착지도 같이 봄
5. 기록: B `data/runs/20261029-025507`(14구간, 앞 10초 버림), M `data/runs/20261029-040156`(보정 7·8·9·10은 앞 5초, 자유 달리기는 바뀐 뒤 10초 버림)

## 판정
- 따라가나: 달리기 구간(B 8에서 10, M 달리기 구간)에서 공중 시간이 속도와 같이 늘어남(순위 상관 > 0)이 **두 기록 모두**, 1 km/h당 크기를 SoundTrackDB(+12 ms)와 비교
- 쓸모 있나: B 8에서 10 구간 하나씩 빼고, 충격 + 새 공중 시간 오차가 충격만(0.37)보다 작은가. 흔들림 폭(0.21)과도 비교
- 한계: 공중 시간 정답 없음 → 정확도는 못 봄. 1명씩·1회. 에어팟이 양쪽 귀를 따로 주는지 미확인(논문은 양쪽 더함)
