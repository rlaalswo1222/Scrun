# 계획 0083: 7세그먼트 모델 다시 학습 — 색이 다른 꺼진 자리·큰 번짐 (BL-17 후속, 지환)

- 상태: **실패(11/27) — 새 모델 안 씀**. 실사진 칸 9개 중 옛 모델 2개 → 새 모델 1개, 공개 test 93.1 → 91.1%. 가설("꺼진 획 색이 달라서")이 틀림. 다음은 앱으로 찍은 사진부터(아래 "다음"). 승인 11/27 지환("규칙 0082 → 재학습 0083 순서로")
- 담당: 지환. 생성기·학습·채점 `speedlab/ocr/`, 모델 파일 `backend/app/console_ocr/models/`(ADR-0012)
- 이어서: 계획 0082(11/27 헬스장 실사진에서 찾은 주원인), 0046(서버 엔진·모델 파일 커밋 규칙)

## 왜
- 11/27 헬스장 러닝머신 A(빨간 LED 7세그먼트, 사진 15장)에서 칸 찾기는 맞았는데 **숫자 읽기가 거의 다 틀림**(정답 있는 9장 중 1장만 맞음): 거리 0.15 → "80.09", 시간 1:09 → "8.08". 숫자 앞 **꺼진 자리가 옅은 베이지·회색 "8"로 비치고**, 켜진 숫자는 크게 번짐
- 꺼진 칸을 지우고 읽혀도 더 나빠짐 → 자르기가 아니라 모델이 이 모습을 모름(가설)
- 생성기(`synth7seg.py`)는 꺼진 획을 **켜진 색을 어둡게** 그림(`on * ghost`). 실물은 **켜진 색과 다른 색**(주변 빛을 받은 옅은 베이지·회색)이고 바탕보다 밝음 → 학습에 없는 모습(가설)
- DRAX 기구(주황·흰 LED)는 지금 모델이 맞게 읽음 → 다시 학습해도 떨어지지 않는지 같이 봄

## 하는 것
1. **생성기**(`synth7seg.py`): LED일 때 꺼진 획을 두 방식 중 하나로 — (가) 지금처럼 켜진 색을 어둡게, (나) **켜진 색과 상관없는 옅은 베이지·회색**(세기 0.15–0.6, 바탕보다 밝게). 번짐 세기·넓이 범위를 넓힘. 미리보기를 실물 자른 그림과 나란히 놓고 눈으로 확인
2. **실사진 칸 채점 세트**(`eval_cells.py`, 로컬 `data/gym_cells/`): 헬스장 사진에서 서버 읽기가 거리·시간으로 이름 붙인 칸을 잘라 정답 글자("0.15", "1.09", "0.018"…)와 함께. **학습에 넣지 않음**(채점 전용). 사진·자른 그림은 저장소에 안 올림(얼굴 비침)
3. **다시 학습**: 새 합성 6,000 + 검증 600(`data/synth_v2`) + 공개 1,636으로 YOLOX-Nano 60 에포크(맥 M5 GPU, 약 67분). `train_yolox.py`에 합성 폴더 인자(`--synth`) 추가
4. **채점**(바꾸기 전 모델 vs 새 모델): 공개 test(202칸), 합성 val, **실사진 칸**, 그리고 사진 단위(헬스장 23장 + 합성 계기판 200장, `bench_det.py`)
5. 좋아지면 `models/yolox_nano_7seg_v2.onnx`로 새 이름으로 넣고(옛 파일은 지움, 0046 README 규칙) `field.py` 기본 경로·README·sha256 갱신 → PR

## 판정
- **실사진 칸 정확도가 오르고**, 공개 test가 2%p 넘게 떨어지지 않고, 사진 단위 **틀린 READ가 늘지 않으면** 바꿈
- 실사진 칸은 한 헬스장·적은 기종이라 숫자는 참고(정확도 아님). 기종이 늘면 다시 채점

## 안 하는 것
- 실사진을 학습에 넣기(라벨링이 필요하고, 채점할 실사진이 남지 않음 — 기종이 더 모이면 따로)
- 표시등으로 칸 뜻을 고르는 기종(My Mountain), LED 깜박임 중간에 찍힌 사진(셔터는 앱 노출 제어 0033과 따로)

## 진행
- 11/27 실사진 칸 세트(`eval_cells.py`, 로컬 `data/gym_cells/`): 서버 읽기가 거리·시간으로 이름 붙인 칸 14개. LED 깜박임 중간에 찍혀 숫자 일부만 보이는 5칸(`_partial`)은 채점에서 뺌 → **온전한 9칸**(러닝머신 A 8칸 + DRAX 천국의 계단 거리 1칸). 정답은 11/27 지환 확인
- **기준(옛 모델)**: 온전한 9칸 중 **2칸 맞음(22%)** — 맞은 것은 p17 거리 0.13, DRAX 0.006. 틀린 것은 앞쪽 꺼진 자리를 숫자로 읽음("80.09", "80.50", "8.0.0")
- 생성기: 꺼진 획 색을 45% 확률로 켜진 색과 상관없는 옅은 베이지·회색(세기 0.15–0.6), 번짐 넓이 0.5–3.0·세기 0.2–1.2(전 0.5–2.0·0.2–0.9), 표시창 둘레 밝은 판(40%), LED 색에 분홍빛 빨강 추가. 미리보기 `runs/gym/synth_v2_preview.jpg`
- 새 합성 `data/synth_v2`(학습 6,000 시드 1, 검증 600 시드 2), `train_yolox.py --synth data/synth_v2 --out runs/yolox_nano_v2` 학습 시작(맥 M5 GPU)
- 11/27 학습 끝(60 에포크 55분, 마지막 검증 공개 valid 93.9%·새 합성 val 97.7%). ONNX `runs/yolox_nano_v2/model.onnx`(3.68 MB, git 밖)

| | 옛 모델(서버) | 새 모델(0083) |
|---|---|---|
| **실사진 온전한 칸 9개**(`eval_cells.py`) | **2** | **1** |
| 공개 test 202칸(`eval.py`) | 93.1% | 91.1% (−2.0%p) |
| 옛 합성 val 600칸(`data/synth/val`) | 99.0% | 96.0% |

- 새 모델도 러닝머신 A의 꺼진 자리 "8"을 숫자로 읽음("80.50", "88.08", "8.0.85"), DRAX "0.006"은 점을 마구 붙임("0...0....06") → **판정 기준 못 넘음, 새 모델 안 씀**
- 모델 입력은 색 그대로(흑백 변환 없음, 학습 때 색조 ±15·채도 0.6–1.4 흔들기) → 색 단서가 없어서가 아님. "꺼진 획 색이 다르다"는 가설이 틀림(또는 그것만으로는 부족)
- 노출 흉내: 자른 칸을 선형 빛으로 −1.5·−3 EV 어둡게 해 옛 모델로 읽혀도 2/9 그대로 — 이미 번진 숫자와 꺼진 자리가 같이 어두워질 뿐, 실제로 어둡게 찍을 때 센서에서 번짐이 줄어드는 효과는 흉내 못 냄
- 같은 날 다른 세션 확인(`docs/product/console_ocr.md` "앱처럼 잘라 다시 채점"): 앱 비율로 잘라도·숫자 띠만 남겨도 맞음 1/13 그대로 → 자르기 문제도 아님. 지환: "앱 인증에선 잘 읽던데" → 남은 차이는 **노출**(앱은 가이드 가운데 기준·−1.5/−3 EV 3장)·3장 중 두 장 일치(가설)
- 정리: 생성기 변경은 `runs/yolox_nano_v2/synth7seg_0083.diff`(git 밖)로 남기고 `synth7seg.py`는 되돌림(서버 모델과 짝). `train_yolox.py --synth` 인자는 남김(다음 실험용)
