# 계획 0058: 계정 삭제 + 카카오 연결 끊기 (BL-48)

- 상태: **승인** (2026-11-19 민재, 정할 것 1–4 모두 (가)) · **구현**(에디터 확인·리뷰 반영 끝, PR 전. 남은 것: 오라클 어드민 키·웹훅 등록(민재), 아이폰 확인)
- 담당: 민재(노션 작업 표 "[BE] 계정 삭제 + 카카오 연결 해제", 11/24 이후 줄을 당겨 옴). 문구·모양은 상준
- 왜: 계정을 만드는 앱은 앱 안에서 계정 삭제를 시작할 수 있어야 App Store 심사를 통과한다(App Store Review Guidelines 5.1.1(v)). 지금 설정 H-10의 "계정 삭제"는 "준비 중"이고 서버 `DELETE /v1/users/me`는 예시 응답(204만 돌려주고 아무것도 안 지움)
- 근거: Figma H-10(610:2647) 아래 "로그아웃 · 계정 삭제", 노트 "계정 삭제는 시연 이후 구현, 심사 제출 전 필수", "계기판 사진은 OCR 직후 삭제"(서버는 사진을 메모리에서만 다룸, 저장 안 함). 확인 화면은 Figma에 없음. 11/06 결정(API 설명): 유예 없이 바로, 모든 데이터 삭제 + 카카오 연결 해제, 카카오가 응답하지 않으면 아무것도 지우지 않고 503. 데이터 모델(계획 0015): 사용자에 딸린 행은 모두 `users`를 지우면 같이 지워짐(ON DELETE CASCADE)
- 카카오 규격(공식 문서 [REST API 연결 끊기](https://developers.kakao.com/docs/latest/ko/kakaologin/rest-api)·[웹훅](https://developers.kakao.com/docs/latest/ko/kakaologin/callback)):
  - 연결 끊기: `POST https://kapi.kakao.com/v1/user/unlink`, `Authorization: KakaoAK {어드민 키}`, 본문 `target_id_type=user_id&target_id={회원번호}`. 동의 철회 + 그 사용자의 카카오 토큰 폐기
  - 연결 끊기 웹훅: 사용자가 카카오계정 "연결된 서비스 관리"에서 끊으면(`referrer_type=UNLINK_FROM_APPS` 등) 카카오가 끊기를 마친 뒤 우리 주소로 `app_id`·`user_id`·`referrer_type`을 보냄(GET 또는 POST), 헤더 `Authorization: KakaoAK {대표 어드민 키}`로 진짜인지 확인, 3초 안에 200

## 하는 것
1. **서버 `DELETE /v1/users/me`를 진짜로**:
   - 순서: 카카오 연결 끊기(어드민 키, 정할 것 1) → 성공하면 한 트랜잭션에서 `users` 줄 삭제(딸린 행은 CASCADE) → 204. 카카오가 실패·시간 초과면 아무것도 안 지우고 503 `SERVICE_UNAVAILABLE`(지금 API 설명 그대로). 카카오가 "이미 연결이 끊긴 사용자"라고 하면 성공으로 봄(웹훅을 놓친 경우)
   - 실시간 방에 붙어 있으면 끊음(허브에서 그 사람 빼기). 기존 액세스 토큰은 이미 "탈퇴한 사용자 토큰이면 401"(`security._user`)이라 따로 할 일 없음, 리프레시 토큰은 CASCADE로 같이 지워짐
   - 설정 `KAKAO_ADMIN_KEY`(없어도 서버는 뜨고 계정 삭제·웹훅만 503 + 시작 때 경고 — 배포와 키 넣기 순서가 바뀌어도 안전하게. fake 모드는 가짜 연결 끊기). 키는 저장소에 안 올림 → 오라클 `.env`에 민재가 직접 넣음(아래 "민재 할 일"), compose가 넘김
2. **연결 끊기 웹훅 `POST·GET /v1/auth/kakao/unlink`**(정할 것 2 가): 헤더 어드민 키·`app_id`가 우리 것인지 확인 → 그 회원번호의 계정을 위와 같이 삭제(카카오 호출 없이) → 200. 모르는 회원번호도 200(카카오가 다시 보내지 않게). 틀린 키는 401
3. **앱 H-10 "계정 삭제"** → 확인 시트(정할 것 3, Figma에 없어 G-11 친구 삭제 시트 모양): 제목 "계정을 삭제할까요?", 지워지는 것(러닝 기록·인증·레벨·친구·주간 목표·보정값), "되돌릴 수 없어요", 카카오 연결도 끊긴다, [계정 삭제](빨강)·[취소]. 누르면 `DELETE` → 성공하면 이 기기 정리(로그인 토큰·가입 직후 표시, 이 계정이 남긴 진행 기록·못 보낸 기록) → 로그인 화면 + "계정을 삭제했어요." 안내. 503이면 서버 안내 문구 + 다시 시도(공통 안내창). 권한 온보딩은 기기 것이라 그대로
4. **확인**: pytest(삭제 뒤 모든 표에서 그 사람 줄 0개, 친구 쪽 친구 목록·피드·함께 달린 러너에서 빠짐, 카카오 실패면 아무것도 안 지움, 이미 끊긴 사용자, 같은 카카오로 다시 가입하면 새 계정, 웹훅 키 틀림 401·맞음 삭제·모르는 회원 200, 실시간 방에서 빠짐), EditMode(시트 글자, 성공 뒤 기기 정리), 에디터 Play(가짜 카카오)로 가입 → 달리기 기록 하나 → 삭제 → 로그인 화면 → 같은 가짜 카카오로 다시 가입하면 빈 계정
5. 문서: `docs/api/` 오류·설명, 개인정보처리방침에 넣을 문구 초안은 상준에게(BL-40)

## 정할 것
1. **카카오 연결 끊기 방법**: (가) **서버가 어드민 키로 끊음 (추천: 앱이 카카오 로그인을 다시 하지 않아도 되고, 서버가 끊기 성공을 확인한 뒤에만 지워서 "우리 쪽만 지워지고 카카오는 연결된 채" 같은 반쪽 상태가 없음. 어드민 키는 서버 `.env`에만)** vs (나) 앱이 카카오 SDK로 끊고 서버는 지우기만(앱이 끊은 뒤 서버 호출이 실패하면 반쪽 상태, 서버가 끊김을 확인 못 함)
2. **카카오 쪽에서 연결을 끊었을 때(웹훅)**: (가) **받아서 계정도 삭제 (추천: 끊긴 뒤엔 같은 카카오로 로그인하면 새 계정이 되고 옛 계정·기록은 아무도 못 쓰는 채 서버에 남음. 개인정보를 쓸모없이 들고 있지 않음)** vs (나) 안 받음(옛 데이터가 남음)
3. **확인을 몇 번**: (가) **시트 한 번(지워지는 것 목록 + 빨간 버튼) (추천: G-11 친구 삭제와 같은 무게, 심사 지침은 "쉽게 찾고 시작할 수 있게")** vs (나) 닉네임을 입력해야 삭제 버튼이 켜짐(실수 방지는 강하지만 단계가 늘어남)
4. **친구의 기록에 남은 "함께 달린 러너" 줄**: (가) **같이 지움(지금 CASCADE 그대로, 마이그레이션 없음) (추천: 지운 사람의 흔적을 남기지 않음. 친구 결과 화면의 함께 달린 러너 수가 하나 줄어듦)** vs (나) 이름 없는 "탈퇴한 러너"로 남김(마이그레이션 필요)
