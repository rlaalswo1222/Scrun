# 계획 0034: 멈추면 아바타도 멈춤 — 걸음으로 바로 멈추고, 위치는 부드럽게 (BL-13, S4 민재)

- 상태: **구현 · 에디터 확인, 아이폰·러닝머신 확인 남음** (2026-11-12 민재 승인: 정할 것 1 (가) 3 km/h 출발, 2 1.2초, 3 `RunnerAnimator` 안 건드림. S4를 미리 함, 11/14 시연 전 머지는 에디터 확인이 끝났을 때만)
- 담당: 민재. `RunnerAnimator`(지환 BL-42)는 정할 것 3
- 기준: 공개 백로그 BL-13 ① 속도 변화가 아바타에 반영 ② 다리는 걸음 감지에 즉시, 위치 이동은 부드럽게 ③ 반영 지연을 재서 기록(Q-11 예비 실험 평균 약 5–6초)

## 지금 (코드에서 확인)
- 섬 아바타 속도 = `NativeSpeedSource.SpeedKmh` = `HasSpeed ? SpeedKmh : 0`. `RunnerController`가 그대로 거리에 더하고, `RunnerAnimator`가 그 속도로 다리를 움직인다
- 벨트에서 내려오면: 걸음 상태가 "없음"으로 바뀌는 데 **2.5초 이상**(`SpeedEstimator.holdS`), 그동안 아바타는 마지막 속도로 계속 달리다가 그 순간 **0으로 뚝** 떨어짐(부드럽지 않음)
- 다시 올라가면: 걸음 상태가 잡히기까지 또 2.5초 이상 제자리
- 센서는 `Steps`(누적 걸음, 감지 지연 없음, 계획 0024)를 이미 주는데 달리기 쪽은 안 씀

## 하는 것
1. **`AvatarSpeed`**(순수 C#, 테스트 가능): 센서 값 → 아바타 속도. `NativeSpeedSource`가 이걸 거쳐 내보냄(속도 소스 안에서 끝, 섬·서버로 가는 거리·속도도 같은 값)
   - **멈춤**: 걸음 수가 **1.2초** 동안 안 늘면 멈춘 것으로 보고 0을 향해 부드럽게 줄임(약 0.6초에 걸쳐). 걸음 상태가 "없음"이 되길 기다리지 않음. 1.2초 근거: 2 km/h 걷기도 70–80 spm(걸음 사이 0.8초 안팎, 10/29 M·B 기록) → 그보다 조금 김(가설, 아이폰·러닝머신에서 확인)
   - **다시 출발**: 걸음 수가 다시 늘면 바로 움직이기 시작(정할 것 1)
   - **속도 변화**: 추정이 바뀌면 위치 속도는 순간 점프 없이 따라감(가속 한도, 초당 약 4 km/h). 추정 자체의 5–10초 지연은 그대로(속도 추정 영역)
   - 센서가 끊기면(폰 데이터 Lost) 멈춤과 같게 → 안내는 BL-15(다음 계획)
2. **지연 기록(③)**: 달리는 동안 이벤트를 기록 — 마지막 걸음 → 아바타 0까지, 첫 걸음 → 아바타 출발까지, 걸음 상태 바뀐 시각. 개발 빌드는 `Documents/run-log/`에 CSV(맥에서 받아 봄), 에디터는 콘솔. 속도 바꿈 → 추정 반영 지연은 헬스장 안내 검증 구간에서 기존 방식으로(`docs/speed/README.md`)
3. 테스트(EditMode): 걸음이 멈추면 1.2초 뒤부터 줄어 0, 걸음이 이어지는 동안은 추정을 따라감, 다시 출발, 가속 한도, 센서 끊김, 지연 기록 값. 에디터 Play: 가짜 센서 10 km/h → Space(정지) → 아바타가 2초 안에 멈춤, 다시 ↑ → 바로 출발

## 정할 것
1. **다시 출발할 때 속도**(걸음은 있는데 추정이 아직 없는 2.5–5초): (가) **느린 걷기 속도(3 km/h)로 출발**하고 추정이 오면 그쪽으로 부드럽게 올라감 **(추천: 러닝머신도 다시 시작하면 낮은 속도에서 올라감. 다리는 바로 움직임)** vs (나) 추정이 올 때까지 서 있음(지금과 같음, 2.5초 넘게 반응 없음)
   - 뺀 안: "멈춘 지 60초 안이면 멈추기 전 속도"(11/12 민재: 말이 안 됨) — 러닝머신은 멈췄다 다시 켜면 낮은 속도부터 올라가고, 앱은 사람이 옆 발판에 섰는지 벨트를 멈췄는지 구분 못 하므로 이전 속도를 가정할 근거가 없음
2. **멈춤 판정 1.2초**: 위 근거대로 1.2초로 시작하고 실기기에서 조정 **(추천)** vs 더 짧게(0.8초, 느린 걷기에서 깜빡일 위험)
3. **`RunnerAnimator`**(지환): (가) 안 건드림 — 속도 소스가 부드럽게 0으로 가면 다리도 따라 멈춤 **(추천: 0029의 약속 그대로, 지환 파일 안 건드림)** vs (나) 다리를 걸음 수에 직접 묶음(지환과 맞춰야 함, 백로그 ②의 "다리는 걸음에 즉시"에 더 가까움)
