계기판 촬영 카메라 — 미리보기를 어디서 그릴까

계획 0033 정할 것 1. Figma E-03은 카메라 미리보기 위에 X·남은 시간·점선 가이드 프레임·셔터가 겹쳐 있다. 노출 제어는 어느 방식이든 Swift(AVCaptureSession)가 한다. 다른 건 미리보기와 겹친 UI를 누가 그리느냐뿐.

Unity가 그림 (C#·UXML·USS) Swift가 그림 (iOS 네이티브) 카메라 영상

1. 화면을 옆에서 본 층

아래가 먼저 그려지고 위가 덮는다. 사용자는 맨 위부터 본다.

(가) 추천

E-03만 Swift 화면

카메라 화면 하나를 Swift가 통째로 Unity 위에 띄운다. 찍으면 닫고 사진 경로를 C#에 돌려준다.

  • + 미리보기가 iOS 카메라 앱처럼 매끄럽고 회전·초점 터치가 기본
  • + 노출 제어·미리보기·찍기가 한 파일, 새로 만들 게 적음
  • − E-03 한 화면은 UXML이 아님 → 상준 UI Kit 값(색·글꼴·버튼)을 Swift로 옮겨야 함
  • − 에디터에선 진짜 E-03이 안 보임(가짜는 바로 사진 3장을 줌)
(나)

프레임을 Unity 텍스처로

Swift는 카메라만 돌리고, 영상 한 장 한 장을 Metal 텍스처로 Unity에 넘긴다. 화면은 전부 UXML.

  • + 모든 화면이 UI Toolkit, 상준 USS 그대로, 지환이 E-03까지 UXML로
  • − 새로 만들 것: Metal 텍스처 넘기기, 텍스처 수명(앱 백그라운드·화면 나감), 회전·좌우, 매 프레임 갱신
  • − 시뮬레이터에 카메라가 없어 이 부분은 실기기 전엔 한 줄도 확인 못 함 → S4 안에 끝낼 위험
  • − 영상 → Unity → 화면으로 한 단계 더 거쳐 미리보기가 조금 늦을 수 있음(가설)
(다) 빼는 게 좋음

미리보기를 Unity 뒤에

카메라 영상을 Unity 뒤에 깔고, Unity가 그 부분만 뚫어서 보이게 한다.

  • + UI는 UXML, 미리보기는 네이티브 속도
  • − Unity 화면 전체를 투명하게 만드는 설정(프레임버퍼 알파)이 섬·달리기 화면 렌더링에도 영향
  • − URP 후처리·배경색이 알파를 덮어써 "검은 화면"이 되기 쉬움, 원인 찾기 어려움

2. 셔터를 누르면 무엇이 오가나

(가) — 사진 경로만 오간다

(나) — 미리보기 동안 매 프레임 텍스처가 오간다

4. 브래킷 3장이란 (정할 것 2)

셔터 한 번에 노출만 다르게 연달아 3장. 10/29 첫 시험에서 같은 계기판을 4초 차이로 찍은 두 장 중 한 장은 LED가 하얗게 타서 숫자가 지워졌다(console_ocr.md). 아래는 그 현상을 설명하려고 그린 그림이고 실제 사진이 아니다.

  • 3장(추천): 계기판 종류(LED·LCD·터치스크린)와 헬스장 조명이 달라도 한 장은 맞을 가능성이 큼. 서버 OCR이 가장 잘 읽힌 장을 고름. 단 올리는 사진이 3배(장당 수백 KB 수준, 가설)
  • 1장: 낮은 노출로 고정. 데이터는 적지만 LCD·터치스크린이 어둡게 묻힐 수 있음
  • 정확한 EV 값(−1.5·−3 등)은 첫 실기기 시험에서 정함. 지금 값은 출발점
