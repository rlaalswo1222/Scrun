## 지금 상태
- 블렌드 트리(`RunnerAnimatorBuilder`): 서 있기 0 + 동작 6개. 기준점은 클립의 디딘 발 속도를 재서 정함: Walking 3.5 / Jogging 6.0 / Slow Run 11.4 / Standard Run 15.6 / Fast Run 18.2 / Sprint 18.8 km/h(지금 controller 값. `unity_map.md`의 3.4·5.2·9.3…은 옛 값)
- `RunnerAnimator`: 블렌드 값 = 속도(최고 기준점까지), 넘으면 재생 속도를 올림
- 10/26 측정(미끄러짐 중앙값): 기준점에서는 ±6% 이내, **기준점 사이에서 큼**(4.5 km/h 19%, 7 km/h 21%). 0에서 3 km/h는 서 있기↔걷기 블렌드라 발이 크게 미끄러지고, 20 km/h는 발 동작이 이상함(사용자 확인)
- 두 클립을 섞으면 발 속도가 두 기준점 사이를 곧게 잇지 않아서 생기는 문제다(가설, 1번 측정으로 확인)

## 하는 것
1. **지금 값 측정**: TestTrack 씬에서 속도를 고정하고 `FootSlipProbe` 중앙값을 잰다. 속도 1·2·3·4.5·6·7·8·10·12·15·18·20 km/h, 각각 5초. 결과는 `data/avatar/`(원본 CSV)와 `unity_map.md`에 남김
2. **발 속도 표로 재생 속도 맞추기**: 블렌드 값 p마다 "섞인 동작의 실제 발 속도 f(p)"를 재서(속도 = p로 달리며 f(p) = p − 미끄러짐) 표로 저장한다. 달릴 때는 블렌드 값 p를 정하고 `animator.speed = 속도 / f(p)`로 재생 속도를 맞춘다 → 어느 속도에서나 디딘 발이 바닥에 붙는다. 대신 발 박자는 표 값만큼 조금 빨라지거나 느려진다
   - 표는 메뉴 `Scrun/Measure Runner Gait`(Play 중 TestTrack에서 0.5 km/h 간격으로 자동 측정)로 만들어 `Resources/RunnerGait.asset`에 저장한다. `RunnerAnimator`가 시작할 때 읽으므로 **섬 씬 파일은 고치지 않는다**(각자 Build Island Scene으로 다시 만드는 파일)
   - 캐릭터나 동작이 바뀌면 메뉴만 다시 실행
3. **0에서 3.5 km/h**: 서 있기와 걷기를 섞지 않는다. 블렌드 트리에서 서 있기를 빼고 "서 있기" 상태와 "달리기" 상태를 나눠 짧게 넘어간다(0.5 km/h 넘으면 걷기, 0.3 km/h 아래면 서 있기). 그 사이 속도는 걷기를 느리게 재생해 발을 붙인다
4. **최고 기준점 넘는 속도(20 km/h)**: 1번 측정을 보고 고친다. 후보: Fast Run(18.2)과 Sprint(18.8)는 기준점이 0.6 km/h만 떨어져 있어 모양이 다른 두 동작이 섞이는 구간이 짧다 → Sprint를 빼거나 최고 동작 하나만 빠르게 재생
5. **확인 기준**: 미끄러짐 중앙값이 3·6·10·15 km/h에서 속도의 5% 이내, 1·20 km/h에서 눈으로 봐서 미끄러지지 않음. 에디터 Play 화면 녹화(전·후)를 PR에 붙임
6. **테스트(EditMode)**: 발 속도 표 읽기(표 사이 보간·범위 밖), 재생 속도 계산(0·표 끝·최고 넘음), 서 있기↔달리기 넘어가는 문턱

## 정한 것
- **Y Bot 동작 `.meta` 5개를 같이 올림**(11/11 지환, 따로 Chore 커밋): 저장소 것은 각 파일이 자기 Avatar를 만드는 설정(`avatarSetup: 1`)인데, 가져오기 코드(`MixamoImportSetup`)의 의도는 서 있기 파일의 Avatar를 공유하는 것(`2`)이다. 처음 올릴 때 서 있기 파일이 아직 안 들어와 있어서 생긴 차이로 보인다(가설). 블렌드 기준점·클립 자르기는 둘이 같다. 측정은 의도대로인 이 맥 설정으로 한다. 안 올리면 가져올 때마다 같은 변경이 다시 생겨 커밋마다 골라 빼야 한다. 팀원은 pull 뒤 Y Bot 5개를 다시 가져오고 같은 상태가 됨
