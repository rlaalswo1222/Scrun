계기판 사진에서 거리·시간 칸 찾기

계획 0042 · 지금 모델은 잘라 놓은 칸 하나만 읽어요. 사진 전체에서 "어느 숫자가 거리고 어느 숫자가 시간인지" 정하는 방법을 고릅니다.

1. 무엇이 어려운가

예시 그림(실제 기종 아님). 10/29 시험 기종은 시간을 "28.40"처럼 점으로 보여 줬어요. 그래서 "콜론이 있으면 시간"만으로는 틀리고, "소수점 둘째 자리면 거리"도 시간과 헷갈려요. 대신 인쇄된 라벨(거리·시간·km)은 일반 OCR이 잘 읽었어요.

2. 추천: B — 글자 영역 찾기 + 라벨로 이름 붙이기

① 영역 찾기PP-OCRv5 검출(DBNet)이 사진의 글자 덩어리를 모두 찾음
→
② 읽기7세그먼트 숫자는 우리 YOLOX, 라벨·LCD 글자는 PP-OCRv5 한국어 인식
→
③ 짝짓기숫자마다 가장 가까운 라벨(거리·DIST·km / 시간·TIME·min)
→
④ 판정거리·시간 후보가 하나씩일 때만 읽음, 아니면 다시 찍기

라벨이 그림(아이콘)뿐이면 ③ 대신 형식 규칙(A)을 씁니다. 그래도 후보가 둘이면 추측하지 않고 다시 찍기로 보내요.

3. 방법 비교

방법좋은 점나쁜 점
A형식 규칙만모델 추가 없음10/29 기종에서 이미 틀림. 속도 8.0·경사 1.5와 헷갈림
B 추천글자 영역 + 라벨 읽기기종을 몰라도 됨. LCD·터치스크린도 같은 길. 모델 둘 다 Apache-2.0서버 모델 약 20MB, 처리 시간 늘어남(오라클에서 잼)
C칸 검출 모델 따로 학습한 번에 끝남여러 기종 실사진 수백 장에 상자 필요. 지금 없음
D사람이 지정(가이드 칸·탭)가장 확실사용자 할 일 늘어남. Swift 촬영 화면·Figma 바꿈, 11/17 "E-04는 사진만"과 다름
✕센서 값과 가까운 칸 고르기쉬움안 씀: 인증은 센서를 확인하는 일이라, 센서로 칸을 고르면 다른 칸이 우연히 맞아도 통과돼요

4. 정할 것

  1. 방법: B + A 보조(추천) / A만 / D
  2. 거리 후보가 둘일 때: UNREADABLE → 다시 찍기(추천) / 미인증 저장
  3. "센서 값으로 칸 고르기 금지"를 계획 0038 독립성 원칙에 더하기(추천)

5. 모르는 것 (가설)

  • 한 칸에 값이 번갈아 나오는 기종(스캔 모드)은 옆 표시등을 읽어야 해요. 실사진을 보고 정해요
  • PP-OCRv5 한국어 인식 88.0%는 PaddleOCR 데이터 기준이라 계기판 라벨 정확도는 몰라요
  • 라벨 위치(칸 위·아래·옆)가 기종마다 달라 "가장 가까운 라벨"이 틀릴 수 있어요 → 실사진 채점으로 확인
