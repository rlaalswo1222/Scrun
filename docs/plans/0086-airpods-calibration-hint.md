# 계획 0086: 에어팟 없이 한 보정으로 에어팟 끼고 달릴 때 — 다시 보정 권하기

- 상태: **승인 · 1·3번 구현(2번은 0번 결과로 안 함)**(2026-11-27 민재: 정할 것 1·2 추천대로 — 달리기 준비 화면, 엔진 변경 같이). 계기: 민재 질문 "에어팟 안 끼고 첫 보정한 다음 뛸 때 끼면 어떻게 돼?"
- 담당: 민재
- **맥 할 일**: Xcode로 `SpeedEstimator.swift` 빌드(Windows에선 컴파일 못 함) → 맥 Swift 재생 도구로 `speedlab/golden/replay_20261029-040156.csv`(새로 만듦)와 같은 값인지 → 아이폰에서 보정 화면 이어폰 칩이 그대로 보이는지
- 이어서: ADR-0005(안내형 보정), ADR-0006(폰은 그냥 올려놓기·사용자 입력 없음), 계획 0024(Swift 속도 플러그인), 0060(달리기 방식)

## 왜 (코드로 확인한 것)
- 보정 단계마다 점 하나: 폰 충격·걸음 수 + **에어팟 흔들림 폭·공중 시간(그 단계에 에어팟 데이터가 70% 이상 들어왔을 때만, 아니면 비움)** (`SpeedEstimator.swift` `stagePoint`)
- 보정점으로 식 두 개(`refit`): **폰 식**(달리기 점 전부) / **에어팟 식**(에어팟 값이 있는 달리기 점만, 없으면 안 만듦)
- 달릴 때(`update`): 에어팟 데이터가 들어오고 에어팟 식이 있으면 에어팟 식, 아니면 폰 식

| 보정 | 달릴 때 | 속도 |
|---|---|---|
| 에어팟 낌 | 낌 | 에어팟 식 |
| 에어팟 낌 | 안 낌 | 폰 식(같은 보정) |
| 안 낌 | 안 낌 | 폰 식 |
| **안 낌** | **낌** | **폰 식 — 에어팟은 걷기·달리기 판정에만 쓰이고 속도엔 안 쓰임** |

- 문제 1: 사용자는 모름. 달리기 준비 화면은 "AirPods 연결됨"인데 속도엔 안 쓰임. 에어팟 없이 보정했다는 표시는 보정 화면 칩("이어폰 없음")뿐이고, 나중에 끼면 다시 보정하라는 안내가 없음
- 문제 2: 보정 도중 에어팟이 끊겨 **에어팟 값이 있는 달리기 점이 하나뿐**이면 에어팟 식 기울기를 B 값(`bFull`)에서 빌림 → 이 사람에게 안 맞을 수 있음(가설)
- 얼마나 손해인지는 **가설**: 10/29 B 기록 1회, 구간 하나씩 빼고 맞히기 충격만 0.37 → 충격 + 에어팟 흔들림 0.21 km/h(지표를 그 기록 보고 고름, `docs/speed/README.md`)

## 하는 것
0. **먼저 재기(PC, 새 실험 없이)**: 에어팟 보정이 있는 기록을 `speedlab/exp/replay_live.py`로 다시 넣어, 같은 보정에서 나온 에어팟 식과 폰 식(`kmh`·`kmhPhone`, 스냅샷에 둘 다 있음)을 계기판 속도와 비교. 기록: 10/29 B(에어팟)·04:01 M, 11/21 워치 기록(에어팟 있으면). 사람별·구간별 오차 표 → `docs/speed/README.md` 실측 줄
1. **에어팟 보정 있음 판정**: 에어팟 값이 있는 달리기 보정점이 **2개 이상**일 때만(앱 C# `CalibrationModel`과 Swift가 같은 기준). 보정 화면 칩("AirPods 연결됨")도 이 기준으로
2. **달리기 준비 화면(RunReady) 이어폰 줄**: 연결됨 + 에어팟 보정 없음이면
   - 줄 상태 "연결됨 · 속도 계산엔 안 써요"(임시 문구, 상준 확인)
   - 아래 한 줄 + 버튼 "AirPods를 끼고 다시 보정하면 더 정확해져요(약 2분)" [다시 보정] / [이대로 달리기]
   - 막지 않음(BL-10 ②와 같이 이어폰은 "없이 진행"). [이대로 달리기]를 누르면 **그 보정에선** 다시 안 띄움(보정이 바뀌면 다시)
3. **엔진**: 에어팟 값 있는 달리기 점이 1개뿐이면 에어팟 식을 만들지 않음 → 폰 식(Swift `refit` + Python `fusion_live.py` 같이, `speedlab/golden/` 정답 파일 다시 맞춤)
4. EditMode: 1번 판정(0·1·2점), 2번 줄 상태 네 경우(위 표), "이대로 달리기" 뒤 같은 보정에선 안 뜸

## 판정
- 0번에서 에어팟 식이 폰 식보다 **기록마다 낫지 않으면** 2번 안내는 넣지 않고(괜히 2분 보정을 권하게 됨) 1·3번만
- EditMode 통과, 에디터 Fake Native로 에어팟 연결·보정 에어팟 없음 조합 확인, 아이폰(맥 묶음): 에어팟 없이 보정 → 끼고 달리기 준비에서 안내 → 다시 보정 → 안내 없음

## 안 하는 것
- 다시 보정 강제, 에어팟 없이 보정 막기(ADR-0006: 사용자 입력 최소, 이어폰은 없어도 달릴 수 있어야 함)
- 에어팟 식을 남의 값으로 채워 바로 쓰기(보정 없이 에어팟을 쓰는 방법은 0번 결과를 본 뒤 따로)

## 정할 것
1. 안내 위치: **달리기 준비 화면**(추천, 에어팟을 실제로 낀 순간) / 홈 / 마이 "속도 다시 맞추기" 옆
2. 3번 엔진 변경을 이 계획에 같이 넣을지(추천: 같이, 판정 기준이 1번과 같아야 해서)

## 진행
- 11/27 **0번 결과(PC, 지금 `fusion_live.py`로 다시 넣음)**: 에어팟이 있는 기록 둘
  - M 10/29 04:01(같은 날 보정, 자유 달리기 달리기 5구간, 바뀐 뒤 10초 뺌): 구간 평균 오차 절댓값 에어팟 식 **0.16**, 폰 식 **0.12 km/h** → 에어팟이 나쁨(10/29 `live_iphone.md` 숫자와 같음, 1명·1회)
  - B 10/29 02:55: 구간 하나씩 빼고 맞히기 충격만 0.37 → 충격 + 에어팟 0.21(`airpods_flight.md`, 지표를 그 기록 보고 고름) → 에어팟이 나음
  - **기록마다 낫지 않음 → 판정대로 2번 안내는 넣지 않음.** 에어팟 비중 `AIR_D = 2.598`이 B 한 사람에게서 배운 값이라 M에 안 맞을 가능성(가설) → 사람별 에어팟 비중을 보정에서 맞출지는 기록이 더 쌓인 뒤 따로
- 11/27 **1·3번 구현**: 에어팟 식은 에어팟 값이 있는 **달리기** 점이 2개 이상일 때만(Swift `airMinPoints`, Python `AIR_MIN_POINTS`, C# `CalibrationModel.HasAirPods`). 보정 화면 이어폰 칩도 이 기준(전엔 "모든 점에 에어팟 값"). EditMode **583 통과**(새 테스트 `에어팟_보정은_에어팟_값이_있는_달리기_점이_둘_이상일_때만`)
  - 정답 파일 `speedlab/golden/replay_20261029-040156.csv` 다시 만듦: 바뀐 줄 32개 모두 보정 도중(25.5–41.0초, 첫 달리기 점 하나만 있던 동안 전엔 B 기울기를 빌린 에어팟 식 → 이제 폰 식), 자유 달리기는 차이 0. 걷기 보정 정답 파일은 그대로
- 11/27 **에어팟 비중 d를 본인 값으로(민재 "사람마다 보정으로 정해야")**: M 04:01 보정 달리기 4점(7·8·9·10)으로 a·b·d를 같이 맞춤 → d = **5.38**(상준 값 2.598), 보정점 잔차 0.12 이하. 자유 달리기 5구간(2초 중앙값으로 같이 다듬어 채점): 상준 d 0.16 · **본인 d 0.26** · 둘 중간 0.21 · 폰 식 0.13 km/h(폰 식 0.12와의 차이는 다듬기를 PC에서 다시 짠 탓)
  - 원인: 보정점에서 ln(충격)과 흔들림 폭의 상관 **+0.98**(둘 다 속도 따라 커짐) → 속도만 올리는 보정으로는 d를 사람별로 못 가름. B의 0.37 → 0.21도 d를 B 기록으로 맞추고 같은 기록으로 채점한 것이라 에어팟 쪽에 유리(가설)
  - 다음(제안, 민재 결정 전): 속도 숫자는 폰 식, 에어팟은 걷기·달리기 판정과 세게 구르기 거르기(계획 0064) 같은 확인용으로. 근거를 늘리려면 에어팟 보정 + 자유 달리기 기록 2–3명 더. 1명·1회라 가설
- 11/27 **공중 시간이 충격보다 일정한가(민재 가설: 충격은 매번 조금씩 달라서 공중 시간을 도입)**: M 04:01 같은 속도 구간 9개(보정 4 + 자유 5, 달리기·에어팟 있는 0.5초 칸, 6초 창 값). 1 km/h당 공중 시간 +9.9 ms · ln(충격) +0.28. 구간 안 흔들림을 속도로 환산하면 **공중 시간 0.52 · 충격 0.20 km/h**, 같은 속도인데 구간 평균이 다른 정도 **0.51 · 0.17 km/h**. 같은 7 km/h가 보정 83 ms · 자유 70–72 ms(충격 0.85 · 0.81/0.72)
  - 같은 날·같은 러닝머신에선 지금 에어팟 공중 시간이 충격보다 덜 일정함. 원래 기대한 "다른 날·다른 기계·폰 위치에도 그대로"는 다른 날 에어팟 기록이 없어 못 잼 → 다음 헬스장: 에어팟 끼고 보정 → 다른 날 보정 없이(같은 러닝머신 + 다른 러닝머신). 1명·1회, 가설
- 11/27 **잠정 방향(민재, 확정 아님)**: 에어팟 없이 뛰어 보니 "0.5 안쪽으로 대충 맞는 듯"(눈으로 본 것, 실측 아님) + 위 결과(같은 날 폰 식이 에어팟 식보다 나음, 본인 비중은 더 나쁨, 공중 시간이 덜 일정함) → **속도는 폰 + 본인 보정만, 에어팟은 걷기·달리기 구분과 상호작용(고개 살짝 젖혀 뒤 보기, 인사 등)에만**
  - 확정하면: 기본 방식에서 에어팟 흔들림 항(상준 비중 2.598) 빼기, 섞기·고치기 실험 방식 정리, ADR-0007 "에어팟으로만 되는 것"의 "걸음 수가 같을 때 속도 가르기"를 새 ADR로 고침, ADR-0007의 안드로이드 다시 검토 조건(폰만 방식이 충분하면)과 연결, 상호작용은 따로 계획(러닝머신 위라 크게 돌리기 말고 살짝 기울이기)
