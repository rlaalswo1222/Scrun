## 테이블 초안 (검토용)
| 묶음 | 테이블 |
|---|---|
| 계정 | `users`(닉네임·키·몸무게·시간대·친구 코드·설정), `auth_identities`(로그인 제공자별 연결, Apple 추가 대비), `refresh_tokens`, `user_agreements` |
| 보정 | `calibrations`(보정값 이력, 마지막 것이 현재. OCR 값 칸 없음 = 독립성 원칙) |
| 목표 | `weekly_goals`(목표 횟수·설정일·다음 주기 예약값). 주기별 진행은 기록에서 계산 |
| 코스 | `courses`(운영 데이터). 맵 인스턴스·실시간 위치는 DB가 아니라 실시간 서버 메모리(BL-25 뒤) |
| 러닝 | `runs`(상태·목표·센서 값·계기판 값·공식 값 출처·미인증 사유·공유 여부, 사용자별 `clientRunId` 유일), `run_samples`(속도 시계열 묶음), `run_companions`(함께 달린 러너) |
| 인증 | `verifications`(시도마다 OCR 결과·대조 표·상태. 사진은 저장 안 함) |
| 고스트 | `run_ghosts`(이 러닝이 어떤 기록을 고스트로 썼나. 기록 자체와 분리 = ③) |
| 보상 | `user_progress`(경험치·레벨·인증 횟수·고른 임팩트, 기록에서 다시 계산 가능한 캐시), `impacts`(목록), `user_impacts`(해금) |
| 친구 | `friendships`(두 사람 한 줄), 피드는 `runs`에서 조회(따로 저장 안 함) |
| 지표 | `events`(PRD 2.4 지표) |
| 운영 | 봇 수·페이스, 레벨 임계값은 테이블 아니라 서버 설정 파일 |

## 미리 정할 원칙 (검토용)
- DB는 PostgreSQL(ADR-0008 제안과 같게)
- ID는 시간순 정렬되는 문자열(ULID 등) + API에선 앞에 종류(`usr_`, `run_`)
- **사용자에 딸린 모든 행은 `users` 삭제 때 같이 지워지게**(ON DELETE CASCADE) → 계정 삭제가 한 줄로 끝남
- 시각은 전부 UTC, 시간대는 `users`에
- 미정인 것은 칸만 열어 둠: OCR 위치(서버 OCR이든 앱 OCR이든 `verifications`에 읽은 값이 들어감), 오프라인 달리기(`clientRunId`로 나중 업로드 가능)

## 하지 않는 것
실제 DB 만들기·서버 코드(BL-44), 계정 삭제 구현(BL-48), 실시간 서버 설계(BL-25), 배포(BL-51)
