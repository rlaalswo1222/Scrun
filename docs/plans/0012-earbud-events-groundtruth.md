# 계획 0012: 이어버드 + 힘판 공개 데이터(Nijs 2021)로 착지·발 떼기 규칙을 정답에 맞추기

- 상태: **완료** (2026-10-29 사용자 "한번 해봐" → 같은 날 분석). 브랜치 `feat/airpods-treadmill`, PC 분석만
  - 고른 규칙(학습 7명): 착지 = 디딤 봉우리 앞 수직 0.2 g 위로, 발 떼기 = 봉우리 뒤 수직 0.3 g 아래로(미분 극값 규칙은 발 떼기 치우침 −108 ms로 꼴찌). 시험 7명 걸음당 공중 오차 11.6 ms(논문 11.9와 같은 수준) → 판정 1 통과. 구간 평균 오차 9.8 ms는 기울기(7 ms/(km/h))의 절반 이하가 아님 → 보정 없이 공중 시간으로 속도는 안 됨. 사람 안 변화는 따라감(상관 +0.92). 우리 기록에서 속도 따라감(B·M 순위 상관 +0.91, +0.92). 결과 [airpods_flight.md](../speed/airpods_flight.md) 끝 절
- 왜: 계획 0011에서 귀 센서 논문(Stuchbury-Wass 외) 방식을 옮겼으나 발 떼기를 디딤 봉우리 바로 뒤로 잡아 실패. 논문 글만으로는 "어느 국소 최솟값"인지 못 정함 → 정답 있는 데이터로 정해야 함. 우리 기록으로 규칙을 고르면 과적합
- 데이터: Nijs, Beek, Roerdink 외, Sensors 2021 21(23):7995 부록(Europe PMC `PMC8659722` 부록 zip). 왼쪽 귀 이어버드 가속도 800 Hz + 힘판 러닝머신, 14명, 7·10·13·최고(16까지) km/h 각 1분, 같은 날 2회. `data/external/nijs2021/`(git 제외)

## 무엇을 (`speedlab/exp/earbud_events.py`)
1. 데이터 구조 확인(축·단위·힘판 정답 형식). 정답 착지·발 떼기 = 수직 힘 문턱(논문이 쓴 값, 없으면 20 N이 아니라 논문 값 확인)
2. 이어버드를 50 Hz로 낮춤(에어팟 조건). 수직 = 중력 방향(저역 필터로 구함) 투영
3. 발 떼기 후보 규칙 몇 개(논문식 국소 최솟값 각 자리, 내려와 0 근처에 닿는 곳 등)와 착지 규칙을 정답과 비교. 사람 나눠서(학습 7명으로 고르고 나머지 7명으로 오차) — 고른 뒤 바꾸지 않음
4. 결과 규칙으로: 걸음당 공중·발 닿는 시간 오차, 구간(1분) 평균 오차, 같은 속도 두 번 사이 차이 → 속도로 바꾸면 몇 km/h인지
5. 고정한 규칙을 우리 B(고상준)·M(민재) 에어팟 기록에 적용: 속도 따라가나, 충격에 더하면

## 판정
- 시험 7명에서 걸음당 공중 시간 평균 오차가 논문(11.9 ms) 근처이고, 구간 평균 오차가 1 km/h당 변화(약 12 ms)보다 충분히 작으면(절반 이하) → 우리 기록에 적용할 가치 있음
- 안 되면: 50 Hz 귀 신호로 발 떼기는 못 잡는다고 기록, 공중 시간은 "수직 0.3 g 아래 시간"(계획 0011)으로만
