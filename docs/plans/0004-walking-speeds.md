# 계획 0004: 걷기 속도(1에서 6 km/h) 실험 + 안내 구간 20초로 + 같은 속도 양방향 측정

- 상태: **구현** (2026-10-28). 1·2 에디터 확인, APK 빌드(17:19), 폰 확인과 3·4(헬스장) 남음
- 작성: 2026-10-28
- 왜: 지금까지 7에서 10 km/h만 측정. 걷기는 걸음 모양·충격이 달라 달리기 충격 모델을 쓰면 틀릴 것(미확인). 걸을 땐 충격이 약해 모터 진동 방식이 통할 수도 있음(가설)

## 무엇을
1. SpeedLab "걷기 안내" 모드: 1, 2, 3, 4, 5, 6, 5, 4, 3, 2, 1 km/h 각 20초 (10/28 저녁 변경, 처음엔 3, 4, 5, 6, 5.5, 4.5, 3.5), 맞추는 시간 5초. **기록만**(달리기 보정에 섞이지 않게), 걷기 모델은 PC에서
2. 안내 검증 구간 60초 → 20초, 순서는 7, 8, 9, 10, 9, 8, 7 → 10, 9, 8, 7, 8, 9, 10 (14구간, 10/28 저녁 변경, 처음엔 8, 10, 7, 9, 8.5, 9.5) (평균 오차만 보면 충분, 피로 섞임도 줄어듦). 오래 달릴 때 틀어지는지는 나중에 따로
3. 다음 헬스장 순서: 벨트만 2·4 km/h(1분) → 걷기(워밍업 겸) → 안내 검증(달리기)
4. 판정(PC): 걷는 중 모터 줄이 보이는지(계획 0002의 순위 판정) / 걷기 전용 충격·걸음 수 모델의 한 속도 빼고 맞히기 오차

6. 벨트만 2, 4 km/h 각 30초(사람은 옆 발판, 실제 속도 버튼으로 표시): 6 km/h 아래 모터 줄 기준. 걷는 중 줄이 안 보일 때 원래 약해서인지 가리려고 (10/28 저녁 추가)
5. 왜 순서를 바꿨나: 10/28 기록에서 내린 속도(7, 8.5)가 +0.8 높게 나온 원인 후보(내린 직후 / 느린 속도 자체 / 정답 기억 착오 / 피로)를 가리려고. 같은 속도를 올라가며·내려가며 재고, 피라미드를 뒤집어 피로와 방향을 떼어 봄
